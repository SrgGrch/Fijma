# Запуск моста в Figma Desktop

Актуальное состояние реализации и оставшаяся Desktop-приёмка: [этап 4](milestone-4.md).

Требуется Node.js 20 или новее. В PowerShell из корня проекта:

```powershell
Set-Location G:\Projects\AI\Figma-plugin-mcp
npm ci
npm run build
```

В Figma Desktop откройте тестовый Design-файл. Выберите Plugins → Development → Import plugin from manifest и укажите `G:\Projects\AI\Figma-plugin-mcp\dist\plugin\manifest.json`. Запустите Figma MCP Bridge из Development. Внешние библиотеки Figma не нужны. Чтение и экспорт доступны после сопряжения; запись включается отдельно переключателем в UI.

## MCP-клиент и сопряжение

Настройте stdio-клиент на команду `node` с аргументом `G:\Projects\AI\Figma-plugin-mcp\dist\server\index.js`. Для клиента с конфигурацией `mcpServers` запись выглядит так:

```json
{
  "mcpServers": {
    "figma-local": {
      "command": "node",
      "args": ["G:\\Projects\\AI\\Figma-plugin-mcp\\dist\\server\\index.js"]
    }
  }
}
```

Клиент запускает stdio-адаптер. Адаптер подключается к общему фоновому мосту и автоматически запускает его, если мост ещё не работает. Повторный запуск Codex использует тот же процесс и порт; stdout занят MCP. Путь к файлу сопряжения сервер выводит в stderr. Если клиент скрывает stderr, используйте из корня ручной SDK-клиент:

```powershell
node scripts/manual-client.mjs
```

Он запускает адаптер общего моста, показывает путь к файлу и принимает по одному JSON-запросу на строку. До сопряжения запрос `{"name":"figma_get_context","arguments":{}}` возвращает `disconnected`.

Откройте указанный в stderr файл `pairing-secret.txt` локально, скопируйте значение в поле ключа плагина. Не передавайте секрет в чат или MCP-запрос. Нажмите «Подключиться и запомнить»: поле очистится, а после успешного согласования ключ сохранится в локальном `figma.clientStorage`. В документ ключ не записывается. При следующем запуске плагин подключится сам; после перезапуска сервера связь восстановится автоматически. Запись при каждом новом соединении выключена. Перечитайте `figma_get_context`: ожидаются `ready`, имя тестового документа, `sessionId` и `connectionGeneration`. Для запросов документа используйте `scope` из этого контекста. После переподключения получите его заново. Второй плагин получает `SESSION_BUSY`.

Сервер слушает `127.0.0.1:55263`, UI подключается к `ws://localhost:55263`, этот адрес разрешён manifest. Для Desktop используйте стандартный порт. `FIGMA_MCP_PORT` меняет только серверный порт: смена endpoint требует согласованного изменения UI и manifest с пересборкой. Значение 0 сохраняет изолированный stdio-сервер для автотестов без фонового процесса. Если порт занят старой версией сервера или session-probe, штатно остановите прежний MCP-клиент; адаптер не завершает владельца порта автоматически и прекращает ожидание запуска через 8 секунд.

## Управление и остановка

UI показывает документ, соединение, Full-document / YOLO, запись, текущую операцию и ошибки. Кнопки и переключатель доступны через Tab и стандартную активацию Enter/Space. «Остановить очередь» выключает запись и прекращает следующие шаги и ожидающие пакеты на ближайшей доступной границе. Уже применённое остаётся в документе. Чтение доступно при выключенной записи.

Для завершения нажмите «Остановить очередь», затем «Отключить» и закройте плагин. «Отключить» приостанавливает автоподключение до нажатия «Подключиться» или нового запуска плагина. «Забыть» разрывает соединение и удаляет ключ из хранилища плагина; после этого потребуется ручное сопряжение. Остановите MCP-подключение в клиенте. В ручном клиенте отправьте `{"action":"quit"}`. Завершение адаптера освобождает владение, сбрасывает связь плагина и сохраняет общий мост и ключ. После восстановления связи запись выключена, контекст нужно получить заново. Закрытие одного плагина не останавливает сервер. Постоянный файл находится в `.figma-mcp-bridge/pairing-secret.txt` домашней папки пользователя, на Windows обычно `C:\Users\<имя>\.figma-mcp-bridge\pairing-secret.txt`. `FIGMA_MCP_PAIRING_DIR` позволяет задать отдельный каталог ключа, например для тестов. На Windows каталог и файл доступны только текущему пользователю; на POSIX используются права 700/600. Повреждённый файл не заменяется автоматически.

Возврат к прежней сборке: остановите общий мост командой ниже и плагин, соберите нужную версию и повторно импортируйте manifest. Изменения документа при этом не откатываются. Для восстановления используйте историю Figma или копию тестового файла. Запрошенное содержимое документа и экспорты передаются MCP-клиенту и выбранному им поставщику модели.

## Candidate для ручной приёмки записи

```powershell
npm run build:candidate
```

Импортируйте `G:\Projects\AI\Figma-plugin-mcp\dist\candidate\manifest.json` и запустите «Figma MCP Bridge - manual test candidate» вместо основной сборки. Обе используют одинаковый runtime записи; candidate предназначен для ручной приёмки в выделенном тестовом файле. Не запускайте одновременно два плагина. Запись включается явно в UI и не требует дополнительных подтверждений каждой правки.

Проверки одним батчем: `npm test`. Это автоматические проверки с имитацией Figma, включая настоящий MCP SDK и loopback WebSocket. Результаты Desktop, измерения лимитов и оставшиеся ограничения приведены в [отчёте](milestone-4.md).

Форматы запросов и ответов: [контракты](../shared/contracts.md). Сопряжение и доставка экспорта: [технический справочник сервера](../server/README.md). Семантика исполнения: [пакеты и восстановление](../shared/execution.md).

## Сохранённое сопряжение и интерфейс

После пересборки плагина полностью закройте его окно и заново запустите через Plugins → Development: кнопка подключения в уже открытом окне продолжает использовать прежний UI-код.

Панель использует цвета текущей темы Figma, показывает соединение, подключённый файл, доступ к записи, активную операцию и последнюю ошибку. При переключении окон или вкладок Figma соединение, очередь и разрешение записи сохраняются: мост продолжает работать с исходным файлом, где запущен плагин. Возвращение к окну не создаёт нового поколения сессии. Повторные попытки после реального обрыва выполняются и в фоне с задержкой 1–15 секунд; настоящее переподключение по-прежнему меняет поколение, выключает запись и требует нового контекста. При `AUTH_FAILED` сохранённый ключ удаляется; `SESSION_BUSY` и ошибки протокола останавливают автоматические попытки. Stop выключает запись и останавливает очередь, сохраняя чтение.

Чтобы перейти к другому файлу, явно отключите плагин в исходном файле и подключите его в новом. Второй плагин не вытесняет первый. Закрытие плагина/его UI, «Отключить», «Забыть» или реальный разрыв связи с плагином сохраняют прежние правила остановки; уже применённые изменения не откатываются. Фоновая работа предполагает, что Figma и плагин продолжают выполняться.

Ключ хранится в профиле Figma для постоянного development ID плагина. У production и candidate разные ID и отдельное сопряжение. Эти локальные ID предназначены для development; для публикации нужен ID, выданный Figma. Смена ID или очистка локальных данных Figma потребуют нового сопряжения. `clientStorage` не является защищённым системным хранилищем: пользователь с доступом к профилю компьютера может извлечь ключ.

«Забыть» удаляет копию ключа из плагина, но не отзывает ключ сервера. Для полного отзыва остановите сервер, удалите только его `pairing-secret.txt` и запустите сервер заново: появится новый ключ, старые сохранённые сопряжения получат `AUTH_FAILED`. Не удаляйте файл работающего сервера: тот продолжает использовать старый ключ до перезапуска.

## Общий мост и несколько клиентов

Каждый запуск Codex использует отдельный stdio-адаптер и MCP-сессию. Команды документа всех клиентов проходят через общую FIFO-очередь; открытое бездействующее соединение не удерживает доступ. Одновременно выполняется одна команда. Размер очереди ограничен согласованным `maxQueuedOperations`, ожидание — `operationTimeout`; переполнение возвращает `RESOURCE_LIMIT`, истечение ожидания — `QUEUE_TIMEOUT` без отправки команды в Figma. Статус и отмена собственных операций обходят очередь. Чужие operationId возвращают `OPERATION_NOT_OWNED`, чужие экспортные ресурсы — `RESOURCE_EXPIRED`.

Отключение клиента удаляет его ожидающие команды, но не разрывает связь с Figma и не меняет разрешения записи. Уже отправленная команда может завершиться; она не повторяется автоматически. После таймаута её результат — `OUTCOME_UNKNOWN`, а новые команды получают `RECOVERY_REQUIRED`, пока не подтверждено завершение. Проверяйте статус своей операции; если остановка не подтверждается, закройте и заново запустите плагин, перечитайте контекст и проверьте документ. После обрыва связи с незавершённой записью требуется новая сессия plugin main; обычный reconnect той же сессии недостаточен. После аварии общего процесса перезапустите MCP-подключение: незавершённые запросы автоматически не повторяются.

Каждый клиент должен сам прочитать контекст перед записью. Между чтением и записью другой клиент может изменить документ: используйте предусловия batch и перечитывайте объекты при `CONFLICT`. Последовательность изменений, которая должна выполняться без чередования с другими клиентами, оформляйте одним batch/execute. Доверенный execute не получает автоматической защиты от устаревших данных.

Адаптеры используют защищённый локальный IPC: named pipe на Windows, Unix socket в каталоге pairing на POSIX. Обе стороны подтверждают знание ключа, не передавая его. Endpoint зависит от каталога pairing и WebSocket-порта. В stderr адаптера выводится PID общего процесса. Внутренний режим `--bridge` запускает мост в текущем процессе; обычная работа не требует ручного запуска.

Общий процесс остаётся после закрытия всех клиентов. Для явной остановки, а также **после обновления сборки**, выполните из корня:

```powershell
node dist/server/index.js --stop-bridge
```

Команда сохраняет ключ и закрывает текущие подключения. Если мост уже остановлен, новый процесс не создаётся. При нестандартных FIGMA_MCP_PORT/FIGMA_MCP_PAIRING_DIR используйте те же переменные и для остановки. Несовместимую старую версию останавливайте её командой или штатным закрытием её клиента, если это сервер до появления общего моста.

Для перехода с прежней сборки один раз закройте MCP-клиент, который держит старый сервер на 55263, соберите новую версию и перезапустите подключение Codex. Конфигурация с `node` и `dist/server/index.js`, manifest и ключ сопряжения сохраняются. Диагностический сервер требует свободного WebSocket-порта: перед его запуском остановите общий мост.

## Обновление доверенного исполнителя

Сервер и плагин обновляются вместе (wire protocol 2); прежняя конфигурация stdio и pairing-ключ сохраняются. Перед запуском новой сборки штатно остановите прежний bridge; не запускайте разные версии против одного плагина. `npm run build` собирает сервер/плагин и статический каталог.

В UI отдельно включается «Разрешить доверенный код». Оно позволяет читать и изменять весь привязанный файл независимо от переключателя строгих batch-изменений и сбрасывается при Stop/переподключении. После отключения клиента отправленный скрипт может продолжать работу. При неподтверждённом завершении мост возвращает RECOVERY_REQUIRED. Закройте и заново запустите плагин, перечитайте контекст и проверьте документ перед новым operationId. Обычный reconnect не доказывает остановку.

Desktop-пробы выполнять по [протоколу](execution-probe.md) в одноразовом файле. Результаты для Figma Desktop 126.11.7, включая Stop, Undo и восстановление после обрыва, приведены в [отчёте](../openspec/changes/universal-executor/verification.md).
