# Запуск моста в Figma Desktop

Актуальное состояние реализации и оставшаяся Desktop-приёмка: [этап 4](milestone-4.md).

Требуется Node.js 20 или новее. В PowerShell из корня проекта:

```powershell
Set-Location G:\Projects\AI\Figma-plugin-mcp
npm ci
npm run build
```

В Figma Desktop откройте тестовый Design-файл. Выберите Plugins → Development → Import plugin from manifest и укажите `G:\Projects\AI\Figma-plugin-mcp\dist\plugin\manifest.json`. Запустите Figma MCP Bridge из Development. Внешние библиотеки Figma не нужны. Чтение и экспорт доступны после сопряжения; запись включается отдельно переключателем в UI.

## MCP-клиент и сопряжение

Настройте stdio-клиент на команду `node` с аргументом `G:\Projects\AI\Figma-plugin-mcp\dist\server\index.js`. Для клиента с конфигурацией `mcpServers` запись выглядит так:

```json
{
  "mcpServers": {
    "figma-local": {
      "command": "node",
      "args": ["G:\\Projects\\AI\\Figma-plugin-mcp\\dist\\server\\index.js"]
    }
  }
}
```

Клиент запускает один процесс сервера. Не запускайте параллельно `npm start` или диагностический сервер на том же порту. stdout занят MCP. Путь к файлу сопряжения сервер выводит в stderr. Если клиент скрывает stderr, используйте из корня ручной SDK-клиент:

```powershell
node scripts/manual-client.mjs
```

Он сам запускает сервер, показывает путь к файлу и принимает по одному JSON-запросу на строку. До сопряжения запрос `{"name":"figma_get_context","arguments":{}}` возвращает `disconnected`.

Откройте указанный в stderr файл `pairing-secret.txt` локально, скопируйте значение в поле ключа плагина. Не передавайте секрет в чат или MCP-запрос. Нажмите «Подключиться и запомнить»: поле очистится, а после успешного согласования ключ сохранится в локальном `figma.clientStorage`. В документ ключ не записывается. При следующем запуске плагин подключится сам; после перезапуска сервера связь восстановится автоматически. Запись включается явно; при временном обрыве она восстанавливается в пределах того же запуска плагина. Закрытие плагина, «Отключить», Stop или ручное выключение записи сбрасывают разрешение. Перечитайте `figma_get_context`: ожидаются `ready`, имя тестового документа, `sessionId` и `connectionGeneration`. Для запросов документа используйте `scope` из этого контекста. После переподключения получите его заново. Второй плагин получает `SESSION_BUSY`.

Сервер слушает `127.0.0.1:55263`, UI подключается к `ws://localhost:55263`, этот адрес разрешён manifest. Для Desktop используйте стандартный порт. `FIGMA_MCP_PORT` меняет только серверный порт: смена endpoint требует согласованного изменения UI и manifest с пересборкой. Значение 0 предназначено для автотестов. Занятый порт приводит к ошибке запуска; старый session-probe на 55263 нужно предварительно остановить.

## Управление и остановка

UI показывает документ, соединение, Full-document / YOLO, запись, текущую операцию и ошибки. Кнопки и переключатель доступны через Tab и стандартную активацию Enter/Space. «Остановить очередь» выключает запись и прекращает следующие шаги и ожидающие пакеты на ближайшей доступной границе. Уже применённое остаётся в документе. Чтение доступно при выключенной записи.

Для завершения нажмите «Остановить очередь», затем «Отключить» и закройте плагин. «Отключить» приостанавливает автоподключение до нажатия «Подключиться» или нового запуска плагина. «Забыть» разрывает соединение и удаляет ключ из хранилища плагина; после этого потребуется ручное сопряжение. Остановите MCP-подключение в клиенте. В ручном клиенте отправьте `{"action":"quit"}`. Штатное завершение закрывает listener и сохраняет ключ для следующего запуска. Закрытие одного плагина не останавливает сервер. Постоянный файл находится в `.figma-mcp-bridge/pairing-secret.txt` домашней папки пользователя, на Windows обычно `C:\Users\<имя>\.figma-mcp-bridge\pairing-secret.txt`. `FIGMA_MCP_PAIRING_DIR` позволяет задать отдельный каталог ключа, например для тестов. На Windows каталог и файл доступны только текущему пользователю; на POSIX используются права 700/600. Повреждённый файл не заменяется автоматически.

Возврат к прежней сборке: остановите сервер/плагин, соберите нужную версию и повторно импортируйте manifest. Изменения документа при этом не откатываются. Для восстановления используйте историю Figma или копию тестового файла. Запрошенное содержимое документа и экспорты передаются MCP-клиенту и выбранному им поставщику модели.

## Candidate для ручной приёмки записи

```powershell
npm run build:candidate
```

Импортируйте `G:\Projects\AI\Figma-plugin-mcp\dist\candidate\manifest.json` и запустите «Figma MCP Bridge - manual test candidate» вместо основной сборки. Обе используют одинаковый runtime записи; candidate предназначен для ручной приёмки в выделенном тестовом файле. Не запускайте одновременно два плагина. Запись включается явно в UI и не требует дополнительных подтверждений каждой правки.

Проверки одним батчем: `npm test`. Это автоматические проверки с имитацией Figma, включая настоящий MCP SDK и loopback WebSocket. Результаты Desktop, измерения лимитов и оставшиеся ограничения приведены в [отчёте](milestone-4.md).

Форматы запросов и ответов: [контракты](../shared/contracts.md). Сопряжение и доставка экспорта: [технический справочник сервера](../server/README.md). Семантика исполнения: [пакеты и восстановление](../shared/execution.md).

## Сохранённое сопряжение и интерфейс

Панель использует цвета текущей темы Figma, показывает соединение, текущий документ, доступ к записи, активную операцию и последнюю ошибку. Скрытие панели сохраняет соединение с тем файлом, в котором запущен плагин; закрытие панели отключает его. Перед записью сверяйте `documentLabel` из свежего `figma_get_context` с нужным файлом, особенно после переключения вкладок Figma. Повторные попытки после обрыва выполняются с интервалом от 1 до 15 секунд. При `AUTH_FAILED` сохранённый ключ удаляется и показывается ввод нового ключа; `SESSION_BUSY` и ошибки протокола останавливают автоматические попытки. Stop выключает запись и останавливает очередь, сохраняя чтение.

Ключ хранится в профиле Figma для постоянного development ID плагина. У production и candidate разные ID и отдельное сопряжение. Эти локальные ID предназначены для development; для публикации нужен ID, выданный Figma. Смена ID или очистка локальных данных Figma потребуют нового сопряжения. `clientStorage` не является защищённым системным хранилищем: пользователь с доступом к профилю компьютера может извлечь ключ.

«Забыть» удаляет копию ключа из плагина, но не отзывает ключ сервера. Для полного отзыва остановите сервер, удалите только его `pairing-secret.txt` и запустите сервер заново: появится новый ключ, старые сохранённые сопряжения получат `AUTH_FAILED`. Не удаляйте файл работающего сервера: тот продолжает использовать старый ключ до перезапуска.
