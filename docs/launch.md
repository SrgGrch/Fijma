# Запуск моста в Figma Desktop

Настройка основных MCP-клиентов приведена в [README](../README.md#как-установить).

Требуется Node.js 20 или новее. В PowerShell из корня проекта:

```powershell
Set-Location G:\Projects\AI\Figma-plugin-mcp
npm ci
npm run build
```

В Figma Desktop откройте тестовый Design-файл. Выберите Plugins → Development → Import plugin from manifest и укажите `G:\Projects\AI\Figma-plugin-mcp\dist\plugin\manifest.json`. Запустите Fijma из Development. Внешние библиотеки Figma не нужны. Чтение и экспорт доступны после сопряжения; запись включается отдельно переключателем в UI.

## MCP-клиент и сопряжение

Настройте stdio-клиент на команду `node` с аргументом `G:\Projects\AI\Figma-plugin-mcp\dist\server\index.js`. Для клиента с конфигурацией `mcpServers` запись выглядит так:

```json
{
  "mcpServers": {
    "fijma": {
      "command": "node",
      "args": ["G:\\Projects\\AI\\Figma-plugin-mcp\\dist\\server\\index.js"]
    }
  }
}
```

Клиент запускает stdio-адаптер. Адаптер подключается к общему фоновому мосту и автоматически запускает его, если мост ещё не работает. Повторный запуск Codex использует тот же процесс и порт; stdout занят MCP. Путь к файлу сопряжения сервер выводит в stderr. Если клиент скрывает stderr, используйте из корня ручной SDK-клиент:

```powershell
node scripts/manual-client.mjs
```

Он запускает адаптер общего моста, показывает путь к файлу и принимает по одному JSON-запросу на строку. До сопряжения запрос `{"name":"figma_get_context","arguments":{}}` возвращает `disconnected`.

Откройте указанный в stderr файл `pairing-secret.txt` локально, скопируйте значение в поле ключа плагина. Не передавайте секрет в чат или MCP-запрос. Нажмите «Подключиться и запомнить»: поле очистится, а после успешного согласования ключ сохранится в локальном `figma.clientStorage`. В документ ключ не записывается. При следующем запуске плагин подключится сам; после перезапуска сервера связь восстановится автоматически. Запись при каждом новом соединении выключена. Перечитайте `figma_get_context`: ожидаются `ready`, имя тестового документа, `sessionId` и `connectionGeneration`. Для запросов документа используйте `scope` из этого контекста. После переподключения получите его заново. Второй плагин получает `SESSION_BUSY`.

Сервер слушает `127.0.0.1:55263`, UI подключается к `ws://localhost:55263`, этот адрес разрешён manifest. Для Desktop используйте стандартный порт. `FIGMA_MCP_PORT` меняет только серверный порт: смена endpoint требует согласованного изменения UI и manifest с пересборкой. Значение 0 сохраняет изолированный stdio-сервер для автотестов без фонового процесса. Если порт занят старой версией сервера , штатно остановите прежний MCP-клиент; адаптер не завершает владельца порта автоматически и прекращает ожидание запуска через 8 секунд.

## Управление и остановка

UI показывает документ, соединение, Full-document / YOLO, запись, текущую операцию и ошибки. Кнопки и переключатель доступны через Tab и стандартную активацию Enter/Space. «Остановить очередь» выключает запись и прекращает следующие шаги и ожидающие пакеты на ближайшей доступной границе. Уже применённое остаётся в документе. Чтение доступно при выключенной записи.

Для завершения нажмите «Остановить очередь», затем «Отключить» и закройте плагин. «Отключить» приостанавливает автоподключение до нажатия «Подключиться» или нового запуска плагина. «Забыть» разрывает соединение и удаляет ключ из хранилища плагина; после этого потребуется ручное сопряжение. Остановите MCP-подключение в клиенте. В ручном клиенте отправьте `{"action":"quit"}`. Завершение адаптера освобождает владение, сбрасывает связь плагина и сохраняет общий мост и ключ. После восстановления связи запись выключена, контекст нужно получить заново. Закрытие одного плагина не останавливает сервер. Постоянный файл находится в `.figma-mcp-bridge/pairing-secret.txt` домашней папки пользователя, на Windows обычно `C:\Users\<имя>\.figma-mcp-bridge\pairing-secret.txt`. `FIGMA_MCP_PAIRING_DIR` позволяет задать отдельный каталог ключа, например для тестов. На Windows каталог и файл доступны только текущему пользователю; на POSIX используются права 700/600. Повреждённый файл не заменяется автоматически.

Возврат к прежней сборке: остановите общий мост командой ниже и плагин, соберите нужную версию и повторно импортируйте manifest. Изменения документа при этом не откатываются. Для восстановления используйте историю Figma или копию тестового файла. Запрошенное содержимое документа и экспорты передаются MCP-клиенту и выбранному им поставщику модели.

Проверки одним батчем: `npm test`. Автоматические тесты используют имитацию Figma и настоящий MCP SDK с loopback WebSocket.

## Сохранённое сопряжение и интерфейс

После пересборки плагина полностью закройте его окно и заново запустите через Plugins → Development: кнопка подключения в уже открытом окне продолжает использовать прежний UI-код.

Панель использует цвета текущей темы Figma, показывает соединение, подключённый файл, доступ к записи, активную операцию и последнюю ошибку. При переключении окон или вкладок Figma соединение, очередь и разрешение записи сохраняются: мост продолжает работать с исходным файлом, где запущен плагин. Возвращение к окну не создаёт нового поколения сессии. Повторные попытки после реального обрыва выполняются и в фоне с задержкой 1–15 секунд; настоящее переподключение по-прежнему меняет поколение, выключает запись и требует нового контекста. При `AUTH_FAILED` сохранённый ключ удаляется; `SESSION_BUSY` и ошибки протокола останавливают автоматические попытки. Stop выключает запись и останавливает очередь, сохраняя чтение.

Чтобы перейти к другому файлу, явно отключите плагин в исходном файле и подключите его в новом. Второй плагин не вытесняет первый. Закрытие плагина/его UI, «Отключить», «Забыть», потеря владельца MCP или реальный разрыв связи сохраняют прежние правила остановки; уже применённые изменения не откатываются. Фоновая работа предполагает, что Figma и плагин продолжают выполняться.

Ключ хранится в профиле Figma для постоянного development ID плагина. Локальный ID предназначен для development; для публикации нужен ID, выданный Figma. Смена ID или очистка локальных данных Figma потребуют нового сопряжения. `clientStorage` не является защищённым системным хранилищем: пользователь с доступом к профилю компьютера может извлечь ключ.

«Забыть» удаляет копию ключа из плагина, но не отзывает ключ сервера. Для полного отзыва остановите сервер, удалите только его `pairing-secret.txt` и запустите сервер заново: появится новый ключ, старые сохранённые сопряжения получат `AUTH_FAILED`. Не удаляйте файл работающего сервера: тот продолжает использовать старый ключ до перезапуска.

## Общий мост и несколько клиентов

Каждый запуск Codex использует отдельный stdio-адаптер и MCP-сессию. Инициализация и список инструментов доступны всем. Первый клиент, вызвавший инструмент (включая `figma_get_context`) или чтение экспортного ресурса, получает владение документом до закрытия соединения. Остальные получают `SESSION_BUSY`: закройте MCP-подключение владельца и повторите запрос в том же клиенте. Таймер простоя и автоматическое вытеснение не используются. Ошибка занятости не требует повторного сопряжения плагина.

Отключение не-владельца не влияет на Figma. При отключении владельца прежняя привязка плагина закрывается; плагин автоматически подключается с новым поколением и выключенной записью. Очередь не переносится, уже применённые изменения остаются. После аварии общего процесса перезапустите MCP-подключение: незавершённые запросы автоматически не повторяются.

Адаптеры используют защищённый локальный IPC: named pipe на Windows, Unix socket в каталоге pairing на POSIX. Обе стороны подтверждают знание ключа, не передавая его. Endpoint зависит от каталога pairing и WebSocket-порта. В stderr адаптера выводится PID общего процесса. Внутренний режим `--bridge` запускает мост в текущем процессе; обычная работа не требует ручного запуска.

Общий процесс остаётся после закрытия всех клиентов. Для явной остановки, а также **после обновления сборки**, выполните из корня:

```powershell
node dist/server/index.js --stop-bridge
```

Команда сохраняет ключ и закрывает текущие подключения. Если мост уже остановлен, новый процесс не создаётся. При нестандартных FIGMA_MCP_PORT/FIGMA_MCP_PAIRING_DIR используйте те же переменные и для остановки. Несовместимую старую версию останавливайте её командой или штатным закрытием её клиента, если это сервер до появления общего моста.

Для перехода с прежней сборки один раз закройте MCP-клиент, который держит старый сервер на 55263, соберите новую версию и перезапустите подключение Codex. Конфигурация с `node` и `dist/server/index.js`, manifest и ключ сопряжения сохраняются.
