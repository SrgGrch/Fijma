# Профиль ограничений

Профиль из `shared/bootstrap-limits.ts` проверен на Windows 11 Pro 26300 и Figma Desktop 126.10.13. Числа ниже — **защитные настройки моста**, не измеренная максимальная производительность Figma и не гарантия для другого файла или компьютера. Фактически согласованный профиль возвращает `figma_get_context.limits`; после переподключения нужно заново получить `scope`. Граница документа 1.2 проверена; запись основной сборки включается явно переключателем UI.

Автотесты с имитацией Figma проверяют логику ограничений; они не измеряют производительность Figma Desktop.

## Параметры и границы

Все размеры — байты UTF-8 или декодированные байты, как указано; время — миллисекунды. Указанный сценарий — способ воспроизведения или автоматический контроль, а не заявление о выполненной Desktop-проверке.

| Параметр | Профиль | Граница и проверка |
| --- | ---: | --- |
| `maxMessageBytes` | 65536 | Ограничение одного сообщения протокола; больше лимита отклоняется. `node tests/pairing.mjs` и `node tests/export-transfer.mjs` проверяют протокол/разбиение, конкретные предельные значения должны проверяться с учётом полной JSON-оболочки. |
| `maxBatchSteps` | 10 | 10 шагов допускаются при выполнении остальных ограничений, 11 отклоняются до записи. |
| `maxQueuedOperations` | 2 | До двух активных/ожидающих операций; новый третий запрос получает `RESOURCE_LIMIT`. `node tests/batch-executor.mjs` проверяет очередь и остановку на имитации. |
| `maxDepth` | 8 | `figma_get_tree` принимает глубину 0–8; 9 в рабочем MCP-маршруте даёт `RESOURCE_LIMIT` (внутренний pager отклоняет её как `INVALID_ARGUMENT`). Обрезание по заданной глубине не означает, что потомков нет. `node tests/tree-pager.mjs`. |
| `maxNodes` | 1000 | Лимит запроса дерева/поиска 1–1000; 1001 недопустим. На странице ответа может оказаться меньше узлов из-за `maxResponseBytes`; продолжение — через `nextCursor`. `node tests/tree-pager.mjs`. |
| `maxResponseBytes` | 32768 | Бюджет ответа ограничивает сериализованную проекцию; дерево резервирует 256 байт на оболочку, продолжение хранится в cursor. При невозможности вернуть хотя бы один узел — `RESOURCE_LIMIT`. Точная граница зависит от имён и UTF-8. `node tests/tree-pager.mjs`, `node tests/read-tree.mjs` проверяют малые искусственные бюджеты. |
| `maxImportBytes` | 262144 | Максимум декодированных байтов PNG/JPEG или UTF-8 SVG; больший ресурс отклоняется. Дополнительный `maxMessageBytes` может ограничить передачу раньше. `node tests/graphics-ops.mjs` проверяет меньший искусственный лимит, MIME и безопасность SVG. |
| `maxExportPixels` | 1000000 | Для PNG предел произведения округлённых ширины и высоты; 1000×1000 укладывается, 1001×1000 превышает лимит. Проверяется до и после экспорта. `node tests/export-plugin.mjs` проверяет искусственный лимит. |
| `maxExportBytes` | 262144 | Размер одного PNG/SVG после нативного экспорта; превышение даёт `RESOURCE_LIMIT`. Доставка идёт ограниченными порциями. `node tests/export-plugin.mjs`, `node tests/export-transfer.mjs`. |
| `operationTimeout` | 30000 | Таймаут ожидания операции сервером; поздний ответ не связывается с новым запросом. Это не обещание прервать синхронный Figma API. `node tests/export-timeout.mjs` воспроизводит сценарий с искусственным коротким таймаутом. |
| `dedupTtl` | 60000 | Окно журнала и допустимый возраст UUIDv7 с допуском `clockSkew`; одинаковый ID/payload не выполняется повторно. После `dedupTtl + clockSkew` старый ID возвращает `OPERATION_EXPIRED`. `node tests/operation-journal.mjs` использует укороченные значения. |
| `maxJournalEntries` | 100 | При 100 неистёкших записях новая операция отклоняется `RESOURCE_LIMIT`; незавершённые записи не вытесняются. `node tests/operation-journal.mjs` проверяет искусственный лимит 1. |
| `resourceTtl` | 60000 | Верхняя граница жизни cursor и экспортного ресурса; после истечения — `INVALID_CURSOR` или `RESOURCE_EXPIRED`. Разрыв сессии может уничтожить ресурс раньше. `node tests/tree-pager.mjs`, `node tests/export-resources.mjs` используют сокращённый TTL. |
| `clockSkew` | 5000 | Допуск UUIDv7: метка более чем на 5000 мс в будущем отклоняется; при проверке возраста добавляется к `dedupTtl`. `node tests/operation-journal.mjs` проверяет искусственный допуск 10 мс. |

## Рабочий мост: команды

Используйте **уже запущенный** ручной MCP-клиент, связанный с выбранным тестовым документом; второй сервер и второй плагин занимают отдельную сессию. Для нового запуска, когда порт свободен, из корня проекта: `node scripts/manual-client.mjs`. Дождитесь `{ "ready": true }`, выполните локальное сопряжение по пути, выведенному клиентом, и не сохраняйте содержимое файла секрета в отчёт. Каждая строка ниже — отдельный JSON-запрос в stdin этого клиента. Клиент печатает структурированный MCP-ответ. Подставьте текущие значения `sessionId`, `connectionGeneration` и nodeId из контекста/фикстуры; примеры заполнены условными значениями.

```json
{"name":"figma_get_context","arguments":{}}
{"name":"figma_get_tree","arguments":{"scope":{"sessionId":"SESSION","connectionGeneration":1},"rootId":"FIXTURE_ID","depth":1,"limit":1000}}
{"name":"figma_get_tree","arguments":{"scope":{"sessionId":"SESSION","connectionGeneration":1},"rootId":"FIXTURE_ID","depth":1,"limit":1000,"cursor":"NEXT_CURSOR"}}
{"name":"figma_get_tree","arguments":{"scope":{"sessionId":"SESSION","connectionGeneration":1},"rootId":"FIXTURE_ID","depth":9,"limit":1000}}
{"name":"figma_get_tree","arguments":{"scope":{"sessionId":"SESSION","connectionGeneration":1},"rootId":"FIXTURE_ID","depth":1,"limit":1001}}
{"name":"figma_export_node","arguments":{"scope":{"sessionId":"SESSION","connectionGeneration":1},"nodeId":"FIXTURE_ID","format":"PNG","scale":1}}
{"name":"figma_export_node","arguments":{"scope":{"sessionId":"SESSION","connectionGeneration":1},"nodeId":"FIXTURE_ID","format":"SVG"}}
```

Повторяйте запрос дерева с теми же rootId/depth/limit и новым одноразовым cursor, пока он есть; изменение документа или параметров может инвалидировать cursor. Зафиксируйте число ответов и узлов, размер каждого ответа в UTF-8 и время каждого вызова, включая масштаб экспорта и итоговые размеры и байты. Инструмент `figma_get_tree` по выбранному root не является document-wide поиском; в тесте загрузки других страниц используйте `node tests/document.mjs` и `node tests/tree-pager.mjs`. Это подтверждает поведение имитации, отдельная Desktop-инструментация загрузки страниц не проведена.

Для ресурсного ответа SVG сначала возьмите `uri` из результата, затем передайте `{"action":"readResource","uri":"RESOURCE_URI"}` до истечения TTL. Ручной клиент сохраняет экспортированные данные во временный файл и сообщает путь; после завершения отправьте `{"action":"quit"}`. В основном плагине кнопка Stop выключает запись и останавливает пакетный executor; текущие getTree и exportNode не получают сигнал отмены. Для них не заявляйте прерывание. В пакетном сценарии фиксируйте интервал от нажатия до результата, статус и завершение текущего вызова. Figma может завершить уже начатый синхронный вызов или exportAsync до обработки сигнала.
