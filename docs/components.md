# Компоненты и экземпляры

Обработчик `componentOperations` реализует создание компонента из новых свойств или существующего узла, объединение локальных компонентов в набор, изменение определений и работу с экземплярами. Основная и candidate-сборки используют этот общий обработчик после включения записи в UI.

`definitions` — частичное обновление: переданные полные имена свойств добавляются или обновляются, остальные сохраняются. У свойств BOOLEAN, TEXT и INSTANCE_SWAP Figma добавляет к имени суффикс `#...`; для изменения необходимо передать полное имя из `componentPropertyDefinitions`. Привязанные значения не заменяются константами. Неизменное значение существующего VARIANT принимается, добавление или изменение через definitions отклоняется до записи. Значения вариантов задаются именами компонентов перед `combineVariants`; результат возвращает фактические определения. Неявного удаления свойств нет.

Создание и смена экземпляра принимают только локальные главные компоненты. `swapVariant` требует варианты одного набора и вызывает `swapComponent`, сохраняя overrides по правилам Figma; в результате указываются фактические свойства и overrides до и после. Для текстовых свойств экземпляра шрифты загружаются до записи. Явный `detachInstance` возвращает ID результирующего frame и отмечает потерю связи. Отделение вложенного экземпляра отклоняется, поскольку Figma также отделила бы его родительские экземпляры.

Структурные изменения и потенциальные циклы проверяются до записи; ошибки после уже успешного вызова API возвращают известные изменения без автоматического Undo. При изменении определения перечисляются известные свойства и сообщается, что экземпляры могут обновиться; их число не вычисляется. Создание набора, изменение main, override, swap и явный detach проверены в Figma Desktop на указанной в [отчёте](milestone-4.md) конфигурации; другие ОС и версии этим прогоном не подтверждены.
