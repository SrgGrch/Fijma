Кодовая готовность candidate и успешные автоматические тесты не означают Desktop-приёмку milestone. Доступность `applyBatch` в context не является списком поддерживаемых op. В candidate реализованы 16 op: `createPage`, `renamePage`, `clonePage`, `deletePage`, `createNode`, `updateNode`, `cloneNode`, `deleteNode`, `setGeometry`, `setConstraints`, `setAutoLayout`, `setLayoutSizing`, `createText`, `setText`, `replaceTextRange`, `formatTextRange`. Для них также действуют ограничения типа узла и полей; объявление в общей схеме не гарантирует поддержку.

Операции этапа 4 с компонентами, вариантами и экземплярами, локальными стилями, коллекциями, режимами и переменными, включая bind/unbind, ещё не реализованы в candidate. Не реализованы также reparent/group/ungroup, appearance, импорт изображений/SVG и boolean-операции. Чтение локальных ресурсов не означает поддержку их записи.

Предварительные лимиты candidate: `maxBatchSteps=10`, `maxQueuedOperations=2`, `maxResponseBytes=32768`. Бюджет фактического readback одного шага — `floor(maxResponseBytes / maxBatchSteps)`, при этих значениях 3276 байт; превышение даёт `RESOURCE_LIMIT` после возможной записи и требует проверки результата и документа. Лимиты подлежат проверке 1.6 и могут измениться: использовать значения из свежего context.

`affectedNodeIds` содержит ID явно записанных узлов, а не исчерпывающий список неявных последствий Auto Layout. Геометрия родителей и детей может присутствовать в readback details; для проверки всех нужных узлов их следует отдельно перечитать. При resize нетекстового узла наличие отсутствующего шрифта где угодно в документе консервативно блокирует операцию, даже если этот текст не находится в его поддереве.

Для воспроизведения автоматических проверок из `G:\Projects\AI\Figma-plugin-mcp`: `npm ci`, `npm run build`, затем `npm test`. Последняя команда также пересобирает диагностические assets через `build:diagnostics`; не запускать её, пока активен замороженный диагностический probe. Адресно можно запустить `node tests/candidate-runtime.mjs`, `node tests/candidate-bridge.mjs`, `node tests/candidate-recovery.mjs`, `node tests/candidate-layout-bridge.mjs`, `node tests/batch-executor.mjs`, `node tests/layout-ops.mjs`, `node tests/text-ops.mjs`, `node tests/text-range-ops.mjs` и `node tests/text-bindings.mjs`; набор имитаций не заменяет Desktop.

## Подготовка

1. Использовать отдельный тестовый файл Figma и записать версию Desktop, ОС, тариф и имя MCP-клиента. На одной странице вручную создать текст `abcTAIL`: для `TAIL` назначить локальный text style и доступную variable binding; остальные символы оставить без них. Убедиться, что используемый шрифт доступен. Записать nodeId и исходные `characters`, `textSegments`, `textStyleId`, `boundVariables` через `figma_get_nodes`.
2. Сначала отдельно выполнить проверку границы 1.2 по разделу «Проверка границы документа и сессии» [инструкции диагностики](../experiments/diagnostics/README.md): manifest — `G:\Projects\AI\Figma-plugin-mcp\experiments\diagnostics\manifest.json`. При подготовке нового запуска выполнить `npm run build:diagnostics`, затем запустить `node dist/diagnostics/controller.js` и оставить controller работающим на протяжении проверки A и B. Не пересобирать и не останавливать уже работающий probe ради подготовки сценария. Исторический session-probe не заменяет эту проверку старого envelope. Диагностическая сборка не доказывает границу рабочего маршрута, поэтому её также нужно проверить на candidate. После окончания диагностики закрыть её плагин и сервер. Затем в корне проекта выполнить `npm ci`, `npm run build`, `node scripts/build-candidate.mjs` и для всех функциональных проверок ниже импортировать один manifest: `G:\Projects\AI\Figma-plugin-mcp\dist\candidate\manifest.json`. `dist/plugin/manifest.json` — production без записи.
3. Настроить MCP stdio-клиент. Пример записи в JSON-конфигурации Windows: `{"command":"node","args":["G:\\Projects\\AI\\Figma-plugin-mcp\\dist\\server\\index.js"]}`. Клиент сам запускает сервер; не запускать второй экземпляр через `npm start`. Освободить порт 55263 от старого session-probe. В stderr сервера найти путь к файлу сопряжения, ввести его содержимое в UI плагина и подключиться. Секрет не помещать в отчёт.
4. После проверки 1.2 включить флажок «Разрешить запись» в candidate UI, если он доступен. Вызвать `figma_get_context({})`, сохранить `sessionId`, `connectionGeneration`, `currentPageId`, capabilities и limits. Далее `scope` — эти sessionId и generation; после переподключения получить свежий context. Продолжать запись только при `ready`, включённой записи и объявленной поддержке команды. Если UI или маршрут не позволяют запись, отметить проверку заблокированной. Предварительный предел — 10 шагов в пакете; сверять его с фактическим context.

Каждый вызов `figma_apply_batch` имеет вид `{scope, operationId, steps:[...]}`. Для каждого нового пакета нужен свежий UUIDv7 в нижнем регистре с текущим временем; одинаковый ID оставляется только для проверки повтора. Сохранять полные ответы и ID узлов, но не секрет. Если возможность отсутствует или получена ошибка, записать ответ и остановить зависимые шаги.

Журнал дедупликации существует только в живом main текущей сессии и не переживает его перезапуск. В пределах окна тот же ID с канонически одинаковым payload возвращает известное состояние без повторной записи; различие порядка ключей объекта не меняет payload. Другой payload с тем же ID даёт `OPERATION_ID_CONFLICT`. Предварительные `dedupTtl=60000` и `clockSkew=5000` мс задают допустимый возраст UUIDv7; при возрасте больше их суммы новый `apply` возвращает `OPERATION_EXPIRED`, даже если запись ещё существует. Перед проверкой сверить актуальные значения в свежем context.

После переподключения для запроса статуса использовать текущий внешний scope: возвращённый результат сохраняет исходное поколение операции. Если исход `unknown` или main перезапущен, перечитать документ и не повторять запись автоматически. Stop отменяет ожидающие и следующие участки, но не откатывает уже выполненное. Предварительный предел журнала — 100 записей; исполняемые и ожидающие записи не вытесняются, а при заполнении возвращается `RESOURCE_LIMIT`. Актуальные лимиты определяет свежий context.

В PowerShell получить новый ID можно командой `node -e 'const b=require("node:crypto").randomBytes(16); b.writeUIntBE(Date.now(),0,6); b[6]=(b[6]&15)|112; b[8]=(b[8]&63)|128; const h=b.toString("hex"); console.log(`${h.slice(0,8)}-${h.slice(8,12)}-${h.slice(12,16)}-${h.slice(16,20)}-${h.slice(20)}`)'`. Генерировать непосредственно перед новым запросом: журнал отклоняет слишком старые ID.

## Экран: чтение → запись → чтение → PNG → Undo

1. Прочитать страницу из context: `figma_get_tree({scope,rootId:currentPageId,depth:2,limit:100})`. Для имеющегося текста прочитать поля `name`, `characters`, `textSegments`, `textStyleId`, `boundVariables`. Зафиксировать также текущую selection: чтение не должно её менять.
2. Создать frame пакетом с единственным шагом `{"stepId":"frame","op":"createNode","type":"FRAME","parent":{"nodeId":"PAGE_ID"},"properties":{"name":"M3 fixture","width":320,"height":160}}`, заменив `PAGE_ID` на currentPageId. Из `steps[0].outputs.nodeId` взять `FRAME_ID` и проверить `succeeded` и `affectedNodeIds`.
3. Создать текст отдельным пакетом: `{"stepId":"text","op":"createText","parent":{"nodeId":"FRAME_ID"},"characters":"Hello 世界","font":{"family":"Inter","style":"Regular"},"typography":{"fontSize":16}}`. Если Inter Regular отсутствует, подставить доступный шрифт и записать его; отсутствующий шрифт не подменять автоматически. Сохранить `TEXT_ID` из результата.
4. Прочитать frame с полями `name`, `children`, `layout`, `width`, `height`. Отдельным пакетом выполнить `{"stepId":"layout","op":"setAutoLayout","target":{"nodeId":"FRAME_ID"},"layout":{"layoutMode":"VERTICAL","paddingTop":16,"paddingRight":16,"paddingBottom":16,"paddingLeft":16,"itemSpacing":8},"expected":{"name":"M3 fixture"}}`. Прочитать оба узла с полями `parentId`, `children`, `layout`, `width`, `height`, `characters`, `textSegments`; неприменимые поля могут быть `unavailable`. Проверить parent, child, текст, применённый layout и фактические конечные размеры. Нельзя считать переданные значения фактическими без повторного чтения.
   Дополнительно проверить refs на свежем пакете: создать frame шагом `frame`, затем text с `parent:{stepId:"frame",output:"nodeId"}`, затем setAutoLayout с `target:{stepId:"frame",output:"nodeId"}` и теми же свойствами layout. Каждый stepId уникален; для нового через ref объекта expected не нужен. Проверить все три результата, полученные nodeId и структуру повторным чтением.
5. Вызвать `figma_export_node({scope,nodeId:FRAME_ID,format:"PNG",scale:1})`; проверить MIME, ненулевые размеры и открыть image block или прочитать возвращённый ресурс до истечения срока. Визуально сверить с canvas и сохранить PNG как доказательство.
6. После завершения всех операций выполнить Undo в Desktop и перечитать узлы. Зафиксировать фактический порядок отмены и размеры; каждый пакет имеет отдельную границу Undo. Не считать Undo атомарным откатом всех пакетов и не запускать глобальный Undo автоматически.

## Существующий текст и ошибки

- **Связи и сдвинутый хвост:** на исходном `abcTAIL` выполнить `replaceTextRange` с `start:0`, `end:3`, `text:"abcd"`, `insertionFormatting:{inherit:"AFTER"}` и `expected` из актуального чтения (`characters` и `textSegments`). Затем перечитать: `abcdTAIL`, хвост сдвинулся с `[3,7)` на `[4,8)`, его style ID и variable binding сохранились. Если реальная Figma не поддерживает сохранение связей, зафиксировать `CAPABILITY_UNAVAILABLE` и отсутствие изменений; молчаливая потеря связи — провал.
- **UTF-16 и шрифты:** на отдельной копии с emoji попытаться задать границу внутри суррогатной пары; ожидать `INVALID_ARGUMENT` без изменения. Повторить создание с намеренно отсутствующим family/style: ожидать `FONT_UNAVAILABLE` без созданного текста. Проверить также редактирование текста со смешанными доступными шрифтами и сохранение хвоста.
- **Ручной конфликт:** прочитать текст, вручную изменить его в Figma и выполнить `setText` со старым `expected.characters`. Ожидать `CONFLICT`, отсутствие перезаписи и возможность увидеть ручной текст при повторном чтении.
- **Повтор:** сразу повторить успешный запрос создания с тем же operationId, scope и идентичным payload. Сравнить результат и дерево: второй объект не создан. Тот же ID с изменённым payload должен дать `OPERATION_ID_CONFLICT`. Записывать отдельно любые ограничения фактического listener.
- **Stop:** отправить пакет из 10 шагов `createNode` с уникальными stepId `stop-1` … `stop-10`, parent равным тестовой странице и именами `stop-1` … `stop-10`. Во время его исполнения нажать доступную с клавиатуры кнопку остановки; затем запросить состояние по operationId и перечитать страницу. Проверить skipped оставшихся шагов, отсутствие записи после stop и отражение уже применённых изменений. Если пакет завершился до нажатия, отметить попытку неубедительной и повторить в подходящий момент. Синхронный вызов Plugin API может завершиться до обработки stop; это не доказательство мгновенного прерывания или rollback.
- **Обрыв и unknown:** инициировать операцию и разорвать соединение до получения окончательного ответа; записать старые scope и operationId. Переподключиться, получить новый context и запросить известное состояние, если маршрут поддерживает старую сессию. При потере журнала или неподдерживаемом восстановлении считать исход неизвестным, перечитать документ и не повторять запись вслепую. Зафиксировать фактический ответ; не выдавать отсутствие дубликата за доказательство восстановления журнала.
