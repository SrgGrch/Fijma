# Исполнитель пакетов

Проверка `renamePage` и `updateNode` с изменением только `name` перечитывает целевые узлы, их геометрию и parentId, не обходит соседей и не возвращает неизменённые children/characters/textSegments. Для остальных операций сохранён обход связанных узлов, включая эффекты компоновки. Бюджет деталей проверки делится на фактическое число шагов пакета, а не на максимальные десять. Этот бюджет не является отдельной гарантией размера полной оболочки при произвольно длинных ID и дополнительных details операции.

`BatchExecutor` подключён к основной и candidate-сборкам; запись доступна после явного включения в UI. Экземпляр и `OperationJournal` принадлежат одной живой сессии. `submit` проверяет scope и общую схему до очереди, резервирует UUIDv7 в журнале и запускает пакеты последовательно. Повтор возвращает известное состояние или результат, не запуская запись. `get` читает живой журнал; `cancel` отменяет одну операцию, `stop` — все текущие и ожидающие. Отключение записи также вызывает `stop`. Отмена проверяется на границах шагов и после асинхронных подготовительных действий, доступна обработчику длительного шага через callback; прервать синхронный вызов API она не может.

Callbacks платформы отвечают за проверку документа и поколения (`checkScope`), загрузку страницы и шрифтов без записи (`prepare`), чтение фактических свойств после загрузки (`readExpected`), применение операции (`execute`) и границу Undo (`commitUndo`). `execute` обязан сообщать об изменении через `record` сразу после каждого успешного изменения, включая промежуточные изменения до возможной ошибки. Иначе исполнитель не сможет узнать об этом изменении. `commitUndo` вызывается после пакета с известными изменениями, включая частичный; глобальный Undo не вызывается. Поведение конкретных действий требуется проверить в Desktop.

`expected` сравнивается только по переданным полям, вложенные объекты и массивы сравниваются полностью, включая порядок. `readExpected` обязан получать живые значения объекта, который изменяет шаг, а не кэш, и выдавать `parentId` и упорядоченный `children` для структурных проверок; текстовые операции должны проверять `characters` и изменяемое форматирование, операции со стилями и переменными — изменяемые свойства и связи общего ресурса. Для перемещения, группировки и других действий с несколькими объектами `expected.related` задаёт отдельные предусловия по ID связанных объектов. Callback обязан возвращать для каждого объекта только запрошенные поля, включая вложенные значения; отсутствие объекта или поля считается конфликтом. Исполнитель сам не доказывает полноту предусловий и не обеспечивает блокировку от ручных правок между проверкой и записью.

Журнал ограничен сессией, допустимым возрастом ID и числом записей; он не сохраняется после перезапуска. `ExecutionTransport` при таймауте ожидания или обрыве возвращает полный конверт `unknown`, не отменяя внутреннее исполнение. После `reconnect` с новым поколением той же сессии команда с любым несовпадающим generation только ищет результат в журнале; если записи нет, возвращается `unknown`. `status` позволяет узнать результат, когда исполнение завершится. Идентичность payload присутствующей записи проверяется журналом. Новый sessionId и повтор текущего поколения при reconnect отклоняются; значения поколений непрозрачны и не обязаны возрастать. История поколений не хранится.

Интеграция обязана сохранять исходный scope каждой команды при reconnect: замена поколения старой команды на новое уничтожает различие между повтором и новой записью. Новый экземпляр плагина получает новый sessionId и новый журнал; потерянную команду из прежней сессии исполнять нельзя. Платформенный `checkScope` обязан также отклонять устаревшую очередь перед очередной записью. Юнит-тесты подтверждают отмену активного и ожидающего пакетов с учётом уже применённого; фактическую остановку кнопкой после частичной записи ещё необходимо проверить в Desktop.

## Доверенный код

Batch и `figma_execute` используют одну очередь и журнал; status/cancel относятся к обоим видам операций. Повтор с тем же ID и исходными языком, кодом, аргументами и scope возвращает существующий результат, а не выполняет код повторно. Разрешение доверенного кода независимо от разрешения batch и сбрасывается при Stop, разрыве и повторном соединении. Во время ожидающего или активного execute чтение документа не запускается.

Тело async-функции получает настоящий `figma`, JSON `args`, ограниченный локальный `console` и `execution.checkCancelled()` / `await execution.yield()`. Скрипт обязан дождаться всей своей работы и не оставлять listeners, callbacks или detached promises, не заменять `figma.ui.onmessage` и не вызывать `closePlugin`. Это доверенное выполнение, не sandbox. Отмена кооперативна и не прерывает синхронный цикл. После начала кода `effects` всегда `unknown`, в том числе при ошибке сериализации; Undo не выполняется автоматически. Граница `commitUndo` вызывается после завершения или ошибки, её работа требует Desktop-проверки.

Результат ограничен JSON DTO: конечные числа, строки, boolean, null, массивы и обычные объекты. Верхний `undefined` становится null; циклы, функции, BigInt, symbols, accessors и объекты API не поддерживаются. Ограничены глубина, количество значений, размер результата и логов; крупный результат передаётся чанками в session resource. Скрипт может намеренно вернуть чувствительное содержимое: автоматической фильтрации нет.
