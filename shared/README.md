# Общие модули (в разработке)

`read-tree.ts` — ограниченный обход переданного поддерева в порядке детей, без загрузки других страниц. Лимит байтов относится к JSON-массиву `nodes`, не ко всему транспортному конверту. Пределы проверяются до обхода, отмена проверяется между узлами, управление уступается каждые chunkSize узлов. `tree-pager.ts` хранит ограниченные продолжения в памяти main: token связан с сессией, поколением, root/depth/limit и ревизией страницы, имеет TTL и расходуется при продолжении. Чужой/изменённый/истёкший cursor отклоняется. Полный поиск ещё отсутствует, поэтому задача 4.2 остаётся открытой.

`operation-journal.ts` — журнал одной живой сессии. Владелец создаёт отдельный экземпляр на sessionId и не переносит его в новую сессию. После проверки сессии/поколения передайте reserve только `{command, params}`: все refs и expected входят в params, транспортное поколение не входит в fingerprint. Только `fresh: true` разрешает новому диспетчеру поставить запись в очередь; `fresh: false` возвращает известное состояние без повторного исполнения. Повтор после смены поколения может только выяснять результат, это проверяет будущий диспетчер до reserve.

ID — UUIDv7 в нижнем регистре, время в миллисекундах. ID старше dedupTtl + clockSkew отклоняется даже после удаления записи. Внутри окна записи не вытесняются; заполнение даёт RESOURCE_LIMIT. Завершённые истёкшие записи очищаются при следующем reserve, queued/running не вытесняются. get неизвестного корректного ID возвращает unknown, а не запускает запись. Потерянный результат может быть уточнён из unknown в конечное состояние. Глобальный Undo и автоматический повтор отсутствуют.

Журнал пока не подключён к исполнителю; задача 5.4 не отмечена завершённой. Чтение дерева и cursor уже подключены к мосту. Лимиты передаются явно: численные эксплуатационные значения будут закреплены после Desktop-замеров задачи 1.6. Журнал не обеспечивает долговечную дедупликацию после перезапуска.

`batch-refs.ts` — независимая проверка ссылок всего пакета до исполнения: известный op, уникальные stepId, только предыдущие шаги и совместимый output для node/style/collection/mode/variable. Ссылки на существующие узлы имеют вид `{nodeId}`, на результат — `{stepId, output}`; существующие ресурсы адресуются строковым ID в предметном поле. Проверка не заменяет схемы обязательных полей операций, finite patches, expected или проверку живого документа. Пока диспетчер и схемы не подключены, задачи 2.1/5.1 остаются открытыми.
