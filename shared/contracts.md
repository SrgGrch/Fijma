# Контракты (реализация продолжается)

Источник входных схем — `contracts.ts`: strictObject отклоняет незаявленные поля, конечные patches зависят от типа узла, ссылки проверяются всем пакетом до исполнения. Схемы MCP публикуются из того же источника через SDK 2.4.0. `zod` уже используется SDK и закреплён как прямая зависимость 4.6.7.

Все десять инструментов перечислены в design §4. Инструменты документа принимают `scope: {sessionId, connectionGeneration}`. Исключение — `figma_get_context`, доступный без плагина. Пример чтения: `{scope:{sessionId:"session",connectionGeneration:1},rootId:"0:1",depth:2,limit:100}`. Для apply_batch дополнительно нужны UUIDv7 operationId и непустой steps.

Ссылка на существующий узел — `{nodeId:"1:1"}`, на результат предыдущего шага — `{stepId:"frame",output:"nodeId"}`. Ресурсные ссылки возвращают styleId, collectionId, modeId или variableId и не могут быть parent узла. updateNode требует явный type для проверки patch до обращения к Figma. Для изменения существующего объекта требуется непустой expected. Проверка живого состояния, загрузка шрифтов и лицензия остаются обязанностью исполнителя, не схемы.

Каталог stdio уже доступен без плагина. Текущий контекст имеет state=disconnected, пустые страницы/selection/capabilities, writeEnabled=false и limits=null: эксплуатационные лимиты ещё не утверждены. При подключённом main get_context возвращает ready и живые страницы/selection; get_tree возвращает nodes/truncated/nextCursor либо структурированную ошибку. Остальные инструменты возвращают NOT_CONNECTED без плагина и CAPABILITY_UNAVAILABLE при подключённом main. Схемы успешных ответов остальных инструментов появятся вместе с обработчиками. Текст и structuredContent совпадают.

`protocol.ts` содержит hello/welcome, предварительные схемы лимитов и проверку конвертов команд по тем же входным схемам. Несовпадающая версия даёт PROTOCOL_MISMATCH, сессия/поколение — SESSION_EXPIRED. ACK возвращает running и никогда не подтверждает succeeded. Схемы результатов, полнота finite fields и подключение проверок на всех границах ещё не завершены: задачи 2.1 и 2.3 остаются открытыми.

Согласование hello/welcome теперь подключено в listener и main, UI выполняет ограниченную маршрутизацию только paired/hello/welcome/bound/error. Сам listener держит новое поколение и очищает привязку после разрыва; счётчик начинается со случайного значения, чтобы перезапуск сервера не возвращал очевидное поколение 1. Диспетчер пропускает только getContext/getTree. Команды записи отклоняются, полный диспетчер и полная проверка UI остаются частью 2.3/3.2.
