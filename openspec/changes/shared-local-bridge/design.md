# Design

## Context

Мотивация и область изменения: [proposal.md](proposal.md). Контракт: [shared-bridge](specs/shared-bridge/spec.md).

Сейчас `server/index.ts` создаёт защищённый постоянный pairing-файл, WebSocket listener, хранилище экспорта и единственный MCP server со stdio transport. `createPairingListener` уже отвергает второй плагин и проверяет scope. `catalog.ts` сохраняет известные ошибки инструментов, но пока не сохраняет SESSION_BUSY при исключении; resource handler преобразует исключения в RESOURCE_EXPIRED. Эти места требуют точечного изменения для контроля владельца.

SDK 2.4.0 `StdioServerTransport` принимает Readable/Writable в конструкторе, обрабатывает end/close/error и поддерживает запись с backpressure. Его можно переиспользовать поверх локального duplex socket без собственного парсера MCP. Существующие интеграционные тесты запускают `server/index.js` с `FIGMA_MCP_PORT=0`, читают адрес из stderr и ожидают завершения при закрытии клиента.

Main specs пока отсутствуют; контракт одного агента находится в change `figma-mcp-bridge-mvp`. Новое изменение сохраняет одного владельца документа, расширяя только число транспортных подключений. Исходные артефакты MVP не переписываются.

## Goals / Non-Goals

**Goals:** переиспользовать listener, каталог, pairing и export store; сохранить команду Codex; убрать конфликт повторных запусков без новых зависимостей; обеспечить безопасную передачу владения.

**Non-Goals:** одновременное редактирование несколькими агентами, выбор нескольких документов, удалённый доступ, служба Windows или автозапуск при входе, автоматическое убийство владельца порта, автоматический повтор запросов после обрыва, GUI управления daemon.

## Decisions

### 1. Три режима одной существующей команды

По умолчанию `server/index.ts` запускает адаптер. Внутренний аргумент `--bridge` запускает общий процесс, `--stop-bridge` выполняет явную остановку. При `FIGMA_MCP_PORT=0` сохраняется прежний изолированный режим, в том числе формат stderr. Недопустимые комбинации аргументов и настройки отклоняются до запуска дочернего процесса.

Общая инициализация переносится из index в runtime с фабрикой MCP-сервера для каждого подключения. Общими остаются только Figma listener и его сессионные ресурсы. Каждая MCP-сессия имеет собственную инициализацию, request IDs и transport. Один MCP server на все подключения не используется: его состояние и callbacks принадлежат конкретному клиенту.

### 2. Локальный IPC вместо нового HTTP API

На Windows используется named pipe через `node:net`, на POSIX — Unix socket внутри защищённого каталога pairing. Endpoint определяется абсолютным нормализованным каталогом pairing и WebSocket-портом. Идентификатор Windows pipe хешируется из этих настроек; длина Unix socket проверяется с понятной ошибкой. Глобальная доступность pipe через readableAll/writableAll не включается.

Это не требует нового TCP-порта, HTTP-маршрутов или изменения manifest. Отдельный произвольный WebSocket endpoint усложнил бы существующую границу подключения плагина. Streamable HTTP здесь не даёт нужной дополнительной возможности.

Перед MCP применяется ограниченный взаимный challenge-response: случайные nonce обеих сторон, версия протокола и HMAC-SHA256 с постоянным локальным ключом. Подписи разделяют роли клиента/сервера и включают оба nonce; сравнение timing-safe. Ключ не передаётся по IPC. Фиксируются максимальный размер кадра аутентификации, время ожидания и число незавершённых подключений. Остаток MCP-потока после handshake не теряется и не обрабатывается до проверки обеих сторон. Handshake отвечает на запрос проверки/подключения и отдельно на аутентифицированный запрос остановки.

После handshake daemon использует существующий SDK transport на socket, адаптер передаёт stdin/stdout через потоковые pipe с backpressure. Лимиты MCP-запросов сохраняются на уровне существующих схем и операций; ошибки IPC не раскрывают ключ и не превращаются в сообщения stdout.

### 3. Запуск по требованию с разрешением гонки на bind

Адаптер сначала пытается подключиться и проверить общий мост. Только отсутствие endpoint позволяет один раз запустить `process.execPath` с тем же entrypoint и `--bridge`, `detached: true`, `windowsHide: true`, независимыми stdio и unref. Ошибка аутентификации или несовместимость не вызывает spawn/retry loop.

Daemon сначала получает исключительное владение существующим TCP-портом Figma, затем публикует IPC. При параллельном запуске один процесс выигрывает bind, остальные корректно завершаются; адаптеры с ограниченным общим deadline повторяют подключение к победителю. Не используются PID-файлы как доказательство жизни или проверка «порт свободен» перед bind.

На POSIX старый socket удаляется только внутри защищённого каталога, только если это socket, и только процессом, уже успешно занявшим WebSocket-порт. Windows pipe исчезает при завершении владельца. Ошибка запуска не должна оставлять занятый WebSocket-порт.

### 4. Владение на срок живого подключения

Инициализация, ping и lists не занимают документ. Общий guard перед каждым tool handler и resource read атомарно назначает первого клиента владельцем либо отклоняет другого с SESSION_BUSY. Проверка выполняется до чтения контекста, ресурса или отправки команды плагину. Существующий enum ошибки уже содержит SESSION_BUSY; каталог должен сохранить её и для инструментов, и для resources.

Первый инструмент, включая `figma_get_context` при disconnected, занимает владение до закрытия адаптера. Таймер простоя и вытеснение не вводятся: между запросами агент может обдумывать ответ, а операция может продолжаться. Другой клиент после SESSION_BUSY может повторить запрос в той же MCP-сессии, когда владелец отключится. Если старый Codex действительно продолжает работать и держит соединение, новый получит SESSION_BUSY; это ожидаемый запрет конкурирующего доступа, а не failed инициализации.

### 5. Передача через сброс связи плагина

На end/close/error адаптера-владельца daemon переходит в состояние освобождения. Listener прекращает старую привязку и закрывает активный WebSocket плагина, существующие pending promises завершаются по текущим правилам, export store закрывается. Только после завершения сброса владение становится свободным. Во время освобождения другие клиенты получают SESSION_BUSY.

Плагин восстанавливает связь через уже существующий remembered-pairing workflow: новое поколение, выключенная запись, обязательное перечитывание контекста, прежний scope недействителен. Старая очередь не переносится; начатая операция останавливается по существующим правилам отключения, уже применённые шаги не откатываются. Передачу необходимо проверить с настоящим runtime плагина в текущем VM harness, включая момент отключения в середине записи.

Отключение не-владельца не трогает Figma. Падение daemon закрывает все адаптеры без прозрачного переподключения и повторного исполнения; восстановление начинается новым запуском MCP-клиента.

### 6. Остановка и обновление

Daemon живёт до явной остановки или аварии, даже без клиентов. `--stop-bridge` проходит ту же аутентификацию и просит daemon закрыть IPC, MCP-сессии, WebSocket и временные ресурсы; постоянный pairing-файл сохраняется. Если процесса нет, команда сообщает это без spawn. Протокол имеет версию; несовместимое соединение требует явной остановки/перезапуска. После обновления сборки документация требует перезапуск daemon, даже если версия IPC не изменилась.

## Risks / Trade-offs

- Живой старый Codex удерживает владение → показать SESSION_BUSY и объяснить закрытие его соединения; не забирать документ по таймеру.
- Фоновый процесс остаётся после закрытия UI → документировать его назначение и команду остановки; не устанавливать системную службу.
- Гонки первого запуска, подготовка ACL и публикация IPC на Windows → процессные тесты параллельного запуска с общим deadline; никаких бесконечных перезапусков.
- Поддельный IPC endpoint → взаимное доказательство владения ключом до MCP; не отправлять bearer secret неаутентифицированному узлу.
- Разрыв во время изменения документа → остановка через существующие границы исполнения, отказ от replay и проверка нового поколения до передачи.
- Поддержка нескольких transport увеличивает количество handles → ограничить незавершённую аутентификацию, очищать закрытые сессии и проверять отсутствие дочерних процессов после тестов.
- Сборка на диске обновилась, daemon ещё старый → явная остановка после обновления; автоматический hot reload не добавляется.

## Migration Plan

1. Собрать и проверить изменение в изолированных тестах, не трогая текущий сервер пользователя.
2. Для перехода определить владельца порта, убедиться, что это прежний сервер проекта, и штатно остановить его MCP-клиент. Не завершать процесс только по номеру порта.
3. Сохранить существующую конфигурацию Codex с `dist/server/index.js`, перезапустить подключение: адаптер поднимет общий мост.
4. Повторно открыть Codex/подключение и проверить отсутствие failed, отдельную инициализацию и SESSION_BUSY при занятом документе. Проверить передачу после закрытия владельца, повторное сопряжение и выключенную запись.
5. При откате выполнить `--stop-bridge`, вернуть прежнюю сборку и запустить один MCP-клиент. Постоянный ключ сохраняется; текущая очередь не переносится.
