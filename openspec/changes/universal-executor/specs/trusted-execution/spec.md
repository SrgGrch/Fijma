# Доверенное выполнение

## Purpose

Выполнять пользовательский код в привязанном документе без расширения каталога предметных команд и без обещаний изоляции, которых доверенный режим не обеспечивает.

## ADDED Requirements

### Requirement: Отдельный доверенный инструмент
Система MUST предоставлять `figma_execute` для JavaScript и TypeScript с scope и operationId. Код MUST исполняться только в plugin main. Строгий batch MUST сохранять свои схемы и MUST NOT автоматически переходить к выполнению кода.

#### Scenario: Новая возможность API
- **WHEN** скрипт использует доступный в текущем редакторе метод, отсутствующий в batch-каталоге
- **THEN** метод доступен без добавления предметной команды; ограничения самого Plugin API сохраняются

#### Scenario: Некорректный исходник
- **WHEN** код не компилируется либо запрашивает неподдерживаемые imports
- **THEN** выполнение не начинается, возвращается ошибка подготовки с местом в исходнике

### Requirement: Явное разрешение и привязка
Execute MUST требовать свежий контекст, актуальные session/generation, право владельца и отдельное разрешение trusted execution в UI. Разрешение MUST сбрасываться при Stop, disconnect и reconnect. Запросы агрегации MUST требовать то же разрешение; параметр readOnly MUST NOT обещать запрет записи.

#### Scenario: Выключенное разрешение
- **WHEN** execute вызван без разрешения, в том числе для подсчёта узлов
- **THEN** запрос отклонён до запуска кода с EXECUTION_DISABLED

#### Scenario: Смена вкладки
- **WHEN** пользователь открыл другую вкладку Figma, но плагин остаётся в исходном файле
- **THEN** execute относится к явно показанному привязанному файлу; система не выдаёт его за новый видимый файл

### Requirement: Общая очередь и повтор
Execute и batch MUST разделять последовательную очередь и пространство operationId. Повтор идентичного запроса MUST возвращать известное состояние без повторного запуска. Другой payload с тем же ID MUST давать OPERATION_ID_CONFLICT. Истёкшие операции и команды прежней сессии MUST NOT запускаться повторно.

#### Scenario: Повтор после потери ответа
- **WHEN** клиент повторил operationId с прежним кодом и scope
- **THEN** возвращается известный результат либо unknown без нового выполнения

#### Scenario: Batch во время скрипта
- **WHEN** скрипт ждёт асинхронный Plugin API, а клиент отправил batch
- **THEN** batch не изменяет документ параллельно со скриптом

### Requirement: Честная отмена и неизвестный исход
Система MUST различать таймаут ожидания и завершение кода. Отмена активного скрипта MUST быть кооперативной; синхронное прерывание не обещается. После потери владельца при незавершённом execute новая работа с документом MUST блокироваться до завершения и безопасного сброса либо перезапуска плагина.

#### Scenario: Таймаут
- **WHEN** сервер перестал ждать ответа
- **THEN** результат unknown, автоматического retry нет, слот выполнения не освобождается только из-за таймаута

#### Scenario: Неотзывчивый код
- **WHEN** код не достигает точки кооперативной отмены
- **THEN** cancel не сообщает о подтверждённой остановке; восстановление требует остановки/перезапуска плагина пользователем

### Requirement: Результат и побочные эффекты
Результат MUST содержать идентификаторы, состояние, ограниченный JSON, логи/предупреждения и ошибку с фазой. Достоверность изменений MUST сообщаться независимо от успеха кода. Система MUST NOT выдавать пустой список affected IDs за доказательство отсутствия изменений, обещать транзакцию или автоматически вызывать глобальный Undo.

#### Scenario: Ошибка после записи
- **WHEN** скрипт изменил узел, затем выбросил исключение
- **THEN** ошибка исполнения возвращается с effects=unknown, без утверждения о rollback или отсутствии записей

#### Scenario: Ошибка сериализации
- **WHEN** возвращённый результат содержит циклы или неподдерживаемые значения
- **THEN** возвращается RESULT_NOT_SERIALIZABLE с фазой serialize; код не запускается снова и возможные изменения не скрываются

### Requirement: Ограниченные ресурсы и диагностика
Система MUST ограничивать исходник, wire-сообщения, JSON-результат, логи и хранилище. Большой разрешённый результат MUST возвращаться через защищённый ресурс с TTL. Ресурс MUST быть недоступен после смены сессии/владельца. Серверная диагностика MUST NOT сохранять код, args, значения результата или пользовательских логов по умолчанию.

#### Scenario: Большой результат
- **WHEN** JSON превышает inline-бюджет, но укладывается в лимит ресурса
- **THEN** ответ содержит краткие метаданные и URI, а передача в сервер ограничена по размеру сообщений

#### Scenario: Переполнение логов
- **WHEN** скрипт превысил бюджет console/log
- **THEN** последующие записи отбрасываются с признаком truncation, без неограниченного накопления

#### Scenario: Ресурс другого владельца
- **WHEN** новый владелец запрашивает прежний URI
- **THEN** содержимое не возвращается

### Requirement: Совместимость среды
Execute MUST быть доступен только при согласованной версии протокола и capability. Неподдерживаемая среда MUST давать CAPABILITY_UNAVAILABLE; старые сервер и плагин MUST отклонять несовместимый handshake. Завершение возвращённого Promise MUST NOT описываться как доказательство отсутствия фоновых callbacks доверенного кода.

#### Scenario: Старая сборка
- **WHEN** подключается плагин с несовместимым протоколом
- **THEN** выполнение блокируется с PROTOCOL_MISMATCH, предлагается согласованное обновление
