# Proposal

## Why

Каталог декларативных операций требует изменения моста для каждого нового свойства Plugin API. Нужен второй путь: выполнить локально подготовленный скрипт над привязанным документом и вернуть небольшой результат, сохранив строгий `figma_apply_batch`.

## What Changes

- Добавить `figma_execute` (рабочее имя в существующем пространстве `figma_*`) для доверенного JavaScript и предварительно преобразованного TypeScript. Чтение и агрегации также разрешены; гарантированного read-only режима нет.
- Разрешение доверенного кода включается отдельно в UI на срок подключения. Операция всегда считается потенциально изменяющей документ.
- Согласовать скрипты с общей очередью, журналом, статусом, отменой, Stop и передачей владельца. Таймаут не означает остановку или отсутствие изменений.
- Добавить ограниченные результаты/логи и MCP resources для больших JSON-результатов; справочник API по закреплённым типизациям с отдельными сведениями о runtime.
- **BREAKING (внутренний протокол):** новая версия согласования, виды операций/результатов и capability. Существующие формы вызова `figma_apply_batch` сохраняются; сервер и плагин обновляются совместно.
- Изменить архитектурный запрет произвольного JavaScript только для явно разрешённого доверенного инструмента. Никакого автоматического fallback из batch в execute.

## Capabilities

### New Capabilities

- `trusted-execution`: контракт выполнения, разрешений, жизненного цикла, результатов и совместимости со строгими операциями.
- `plugin-api-catalog`: доступный по ресурсам справочник API с сигнатурами, ограничениями, примерами и фактическими признаками среды.

### Modified Capabilities

Основной каталог `openspec/specs` пока пуст (`openspec list --specs`). Поэтому MODIFIED delta к отсутствующим main specs не создаётся. В design явно описано, какие положения прежних change-спецификаций новое предложение заменяет; их согласование включено в разработку.

## Impact

Основа: commit `0b0d6a7`, 2026-11-05. Затронуты shared contracts/protocol/journal/executor, server catalog/listener/runtime/daemon/resources, plugin runtime/UI, сборка и тестовые fixtures. Точная карта — в design.

Это план следующего этапа, а не уже реализованный режим. Контролируемый интерпретатор, принудительное прерывание, полноценная изоляция JavaScript, внешние npm imports и HTTP API не входят в первую поставку. Существующий loopback-канал, pairing и один владелец сохраняются. Postman HTTP-коллекция здесь не добавляет проверки: контракт — MCP и сообщения плагина, проверяемые существующими harness.
