# План разработки Figma MCP Bridge MVP

Отмечены только полностью выполненные пункты. Требования: [specs](specs/); решения и таблица покрытия исходного документа: [design.md](design.md). Проверки в Desktop выполняются на отдельном тестовом файле.

## 1. Проверка совместимости и основа проекта

- [x] 1.1 Выбрать совместимые runtime, MCP SDK и клиент, закрепить версии и минимальные команды сборки сервера/main/UI; проверка: чистая установка и сборка проходят, manifest импортируется в Figma Desktop, окружение записано в отчёт совместимости.
- [ ] 1.2 Проверить реальный loopback WebSocket и manifest на целевой ОС, main/UI message passing, смену вкладки, закрытие/перезапуск main и отсутствие обязательного fileKey; проверка: таблица событий и эксперимент показывают, что старая команда не меняет другой документ. При невозможности обеспечить границу зафиксировать блокер до основного редактирования.
- [x] 1.3 Проверить commitUndo между двумя пакетами, после частичного шага и при промежуточных ручных правках; проверка: записан фактический результат Undo с версиями Desktop/ОС, без заявления о транзакционной изоляции.
- [x] 1.4 Проверить PNG image block, SVG и MCP-ресурс с выбранным реальным клиентом; проверка: агент получает изображение тестового фрейма либо явно зафиксировано ограничение выбранного способа и проверен доступный путь получения экспорта.
- [x] 1.5 Проверить доступность локальных компонентов, text/paint/effect/grid стилей, коллекций, modes, aliases и bindings на целевой лицензии; проверка: отчёт перечисляет поддерживаемые действия и воспроизводимые ошибки ограничений без подмены константами.
- [ ] 1.6 Измерить ограниченное чтение большого тестового файла, экспорт и задержку stop; закрепить все лимиты из design §8 и команды воспроизведения. Проверка: опубликованы численные параметры и граничные случаи для последующих тестов; остальные страницы не загружаются ради обычного запроса поддерева.

## 2. Схемы и протокол

- [x] 2.1 Реализовать общие схемы всех MCP-инструментов из design §4, конвертов, ссылок, шагов, finite patch-полей по типам, expected, состояний и ошибок; проверка: валидные примеры всех групп проходят, неизвестные поля/команды, неверные типы refs и несовместимые значения отклоняются. Добавить читаемый справочник контрактов рядом со схемами.
- [x] 2.2 Реализовать stdio-каталог MCP и согласование версии, input/output schemas, structuredContent и isError; проверка: контрактный клиент получает инструменты без плагина, различает protocol/tool errors, stdout не содержит диагностики.
- [ ] 2.3 Реализовать hello/welcome и проверку внутренних сообщений на границах server/UI/main; проверка: несовместимая версия и повреждённые сообщения не доходят до записи, ACK не превращается в succeeded.

## 3. Сессии, сопряжение и UI

- [x] 3.1 Реализовать loopback listener, случайный секрет, защищённый локальный файл, аутентификацию первого сообщения и ограничение неавторизованных соединений; проверка: неверный секрет и нелокальное подключение отвергаются, секрет отсутствует в URL, MCP-ответах и логах. Документировать локальное сопряжение.
- [ ] 3.2 Реализовать sessionId, connectionGeneration, повторное чтение контекста, отклонение второго клиента/плагина и старых очередей; проверка: тесты restart/reconnect/wrong-document/SESSION_BUSY и реальная смена вкладок из 1.2 не меняют чужой документ.
- [ ] 3.3 Создать UI со статусом, именем документа, Full-document / YOLO, writeEnabled, текущей операцией, ошибками и доступными с клавиатуры stop/disconnect; проверка: состояние видно и без цвета, управление записью работает с клавиатуры, чтение доступно при writeEnabled=false.
- [ ] 3.4 Документировать запуск сервера, импорт manifest, настройку stdio-клиента, сопряжение и остановку; проверка: инструкция воспроизводится с чистой сборкой и не требует внешних библиотек Figma или дополнительных подтверждений правок.

## 4. Чтение и навигация

- [x] 4.1 Реализовать контекст, страницы, выделение и загрузку только нужной страницы; проверка: пустой файл, необязательный fileKey и чтение другой страницы проходят без полной сериализации документа и без смены выделения.
- [x] 4.2 Реализовать дерево, поиск, лимиты и cursor с областью/фильтрами/сессией; проверка: depth/node/byte лимиты и продолжение работают на большом дереве, изменённый или чужой cursor даёт INVALID_CURSOR.
- [ ] 4.3 Реализовать проекции scene nodes и локальных ресурсов с mixed, связями, скрытыми/locked флагами; проверка: отсутствующий узел отличается от недоступного свойства, переменные и стили читаются вне дерева scene nodes. Добавить примеры чтения в справочник инструментов.
- [ ] 4.4 Реализовать явный переход к узлам и сессионный кэш с инвалидированием; проверка: только navigate меняет viewport/selection, ручная правка видна при следующем чтении и проверке перед записью.

## 5. Исполнение пакетов и восстановление

- [ ] 5.1 Реализовать последовательную очередь, preflight всего пакета и refs на предыдущие шаги; проверка: два пакета не перемешиваются, duplicate stepId/forward refs/type mismatch не оставляют изменений.
- [ ] 5.2 Реализовать expected по живым значимым свойствам после загрузки зависимостей; проверка: ручные изменения текста, родителя, порядка детей и общего ресурса дают CONFLICT без молчаливой перезаписи. Документировать набор предусловий каждого действия.
- [ ] 5.3 Реализовать stop-on-first-error, результаты всех шагов и учёт изменений внутри упавшего шага; проверка: ошибка после создания фрейма возвращает partially_applied, ID созданного и skipped следующих шагов без обещания rollback.
- [ ] 5.4 Реализовать живой журнал, fingerprint, допустимый возраст operationId и запрос состояния; проверка: потеря ответа и повтор не создают дубликатов, изменённый payload даёт OPERATION_ID_CONFLICT, истёкший ID не исполняется, заполнение журнала даёт RESOURCE_LIMIT. Описать границы дедупликации.
- [ ] 5.5 Реализовать отмену, приоритет UI stop/write-disable и границы Undo; проверка: остановка прерывает ожидающие записи и следующие шаги, возвращает применённое, не вызывает глобальный Undo; Desktop-поведение совпадает с 1.3.
- [ ] 5.6 Обработать обрыв, смену поколения и таймаут после возможной записи; проверка: статус восстанавливается из живого плагина, а после потери состояния остаётся unknown без автоматического повтора в новой сессии.

## 6. Структура, компоновка и оформление

- [ ] 6.1 Реализовать create/rename/clone/delete страниц и базовых типов узлов; проверка: отдельные редактируемые объекты возвращают ID, удаление последней страницы и прочие ограничения API не обходятся. Дополнить справочник поддерживаемых типов.
- [ ] 6.2 Реализовать reparent, layer order, group/ungroup с явной семантикой координат; проверка: перемещение между страницами сохраняет корректные связи, цикл/неверный parent/instance constraints отклоняются без detach.
- [ ] 6.3 Реализовать geometry, constraints, Auto Layout, wrap и режимы размеров; проверка: fixture экрана после записи имеет ожидаемую структуру и фактические границы, неверные числа и несовместимые параметры отклоняются.
- [ ] 6.4 Реализовать fills/gradients/strokes/opacity/corners/effects и явные изменения locked; проверка: частичный update сохраняет незаданные свойства, блокировка не снимается скрыто. Добавить примеры частичного обновления.
- [ ] 6.5 Реализовать импорт байтов изображений и SVG с ограничением объёма и проверкой внешних ссылок/скриптов; проверка: корректные ресурсы создаются, неверный MIME, внешний URL/путь, опасный или слишком большой SVG отвергаются до записи и без сетевого запроса.
- [ ] 6.6 Реализовать union/subtract/intersect/exclude; проверка: Desktop-фикстуры подтверждают тип и геометрию результата, запрос vectorNetwork отклоняется без обходного исполнения кода.

## 7. Текст

- [ ] 7.1 Реализовать определение/загрузку необходимых шрифтов, создание text и изменение типографики; проверка: single/mixed/missing fonts обрабатываются, отсутствующий шрифт не заменяется и не оставляет частично изменённый текстовый шаг.
- [ ] 7.2 Реализовать formatTextRange и replaceTextRange с UTF-16 границами и явным оформлением вставки; проверка: более длинная замена сохраняет стили сдвинутого хвоста, emoji не делятся, неверные диапазоны отклоняются.
- [ ] 7.3 Обеспечить сохранение незатронутых text styles и variable bindings; проверка: Desktop-пример существующего экрана сохраняет смешанное форматирование и связи. Документировать полную замену, диапазоны и правила наследования.

## 8. Локальная дизайн-система

- [ ] 8.1 Реализовать создание/преобразование компонентов, component sets и свойства вариантов; проверка: созданный набор имеет читаемые связи и свойства, изменение main отражается в допустимых экземплярах. Добавить пример локальной библиотеки.
- [ ] 8.2 Реализовать создание instance, свойства, swap variant и явный detach; проверка: связи и допустимые overrides сохраняются, только detachInstance отделяет экземпляр, структурная ошибка не запускает detach автоматически.
- [ ] 8.3 Реализовать CRUD, применение и явное снятие локальных paint/text/effect/grid стилей; проверка: общий стиль меняет два связанных узла, удаление сообщает известные последствия, внешняя библиотека даёт CAPABILITY_UNAVAILABLE.
- [ ] 8.4 Реализовать CRUD коллекций/переменных/режимов и значения по modeId; проверка: типизированные значения читаются обратно, ограничения целевой лицензии из 1.5 возвращают понятные ошибки без обхода.
- [ ] 8.5 Реализовать aliases, bind/unbind и режимы узлов; проверка: alias cycle/type mismatch отклоняются, незатронутые связи сохраняются, замена токена константой требует явной операции. Документировать ограничения и побочные эффекты общих ресурсов.

## 9. Проверка результата, ресурсы и диагностика

- [ ] 9.1 Реализовать обязательное чтение затронутых свойств после записи, affected nodes/resources и удалённые объекты; проверка: ответ содержит фактические Auto Layout размеры, сбой проверки не выдаётся за подтверждённый успех.
- [ ] 9.2 Реализовать PNG/SVG экспорт и проверенный в 1.4 способ MCP-доставки; проверка: реальные клиент и агент получают изображение изменённого фрейма, экспорт сверх лимита даёт RESOURCE_LIMIT без скрытого изменения масштаба.
- [ ] 9.3 Реализовать сессионные ресурсы, сроки жизни, очистку при окончании сессии и ограничения чтения URI; проверка: истёкший/чужой URI не раскрывает файл, временные данные удаляются. Документировать получение и срок хранения экспорта.
- [ ] 9.4 Реализовать метаданные журнала, редактирование чувствительных данных, явное включение и очистку диагностики; проверка: тестовые секрет/текст/изображение отсутствуют в стандартных логах и ошибках, secret отсутствует и в расширенной диагностике.

## 10. Сквозная приёмка полного MVP

- [ ] 10.1 В реальном Desktop выполнить сценарии существующего экрана и создания нового: чтение → текст/Auto Layout/ресурсы → повторное чтение → PNG; проверка: сохранены незатронутые форматирование и связи, новые узлы редактируемы, отчёт содержит окружение и результаты.
- [ ] 10.2 В тестовом файле проверить YOLO на другой странице, массовом удалении и общих локальных ресурсах, затем отказ записи в другой файл; проверка: дополнительных approval-шагов нет, межсессионная запись отклоняется, stop работает с клавиатуры.
- [ ] 10.3 Выполнить сквозные сбои: потеря ACK/результата, повтор, частичный шаг, ручной конфликт, рестарт, второй клиент/плагин и исчерпание ресурсов; проверка: нет дубликатов, молчаливых перезаписей и автоматического Undo, известные/неизвестные исходы различимы.
- [ ] 10.4 Сверить весь §13 исходного дизайна и матрицу design §9 с результатами, запустить сборку и контрактные проверки из 1.1; проверка: отчёт явно отделяет автоматические проверки от Desktop, указывает поддержку клиента/лицензии и оставшиеся ограничения. Полный MVP не объявляется готовым без группы 8.
