# Сессия локального моста

## Purpose

Привязать одного агента к одному живому документу Figma и сохранить эту границу при отключении, смене документа и перезапуске плагина.

## ADDED Requirements

### Requirement: Локальное соединение с сопряжением
Сервер MUST обслуживать MCP через stdio, принимать WebSocket только на loopback и требовать секрет сопряжения до допуска к документу. Секрет MUST NOT попадать в результаты инструментов, URL или журналы.

#### Scenario: Успешное сопряжение
- **WHEN** UI development-плагина в Figma Desktop предъявляет действительный секрет локальному мосту
- **THEN** мост разрешает согласование протокола и регистрацию сессии

#### Scenario: Неавторизованное соединение
- **WHEN** клиент обращается без секрета, с неверным секретом или через нелокальный интерфейс
- **THEN** доступ к командам и сведениям документа отсутствует; знание порта или допустимый origin не заменяют сопряжение

### Requirement: Единственный агент и документ
Система MUST обслуживать не более одной активной сессии плагина и одного MCP-клиента. Второе подключение MUST быть явно отклонено без вытеснения первого и без выбора документа по имени.

#### Scenario: Второй плагин или клиент
- **WHEN** при активном соединении подключается другой плагин или MCP-клиент
- **THEN** новое подключение получает SESSION_BUSY, а команды первого продолжают адресоваться исходной сессии

### Requirement: Явная привязка команды к документу
Каждая команда к документу MUST содержать sessionId и connectionGeneration. Система MUST проверять их до постановки в очередь и перед исполнением; идентификаторы узлов действуют только в этой сессии. Работа MUST быть возможна без figma.fileKey.

#### Scenario: Совпадающие имена файлов и узлов
- **WHEN** старая команда предъявлена с именем или nodeId, совпадающим в другом документе
- **THEN** команда отклоняется по сессии, а другой документ не изменяется

#### Scenario: fileKey недоступен
- **WHEN** локальный плагин не получает fileKey
- **THEN** сопряжённая сессия продолжает работу, а UI показывает доступные сведения документа без использования имени как идентификатора

### Requirement: Переподключение и перезапуск
Система MUST менять поколение при новом соединении и sessionId при новом запуске плагина. После потери связи запись MUST ждать повторного чтения контекста; старая очередь MUST NOT переноситься в новую привязку. Переключение документа MUST аннулировать прежнюю привязку.

#### Scenario: Перезапуск плагина
- **WHEN** плагин перезапущен и агент получил новую сессию
- **THEN** старые команды получают SESSION_EXPIRED; агент читает новый контекст и может работать без дополнительного пользовательского подтверждения

#### Scenario: Восстановление живого плагина
- **WHEN** WebSocket восстановлен без перезапуска плагина
- **THEN** sessionId сохранён, поколение обновлено, старые сообщения отклоняются, а состояние прежней операции можно выяснить отдельно

### Requirement: Полный доступ без подтверждений
После сопряжения система MUST разрешать поддерживаемые изменения всего текущего документа без approval-шагов, включая массовое удаление и общие локальные ресурсы. Валидация и ограничения Figma MUST сохраняться.

#### Scenario: Запись вне выделения
- **WHEN** агент меняет узлы другой страницы или удаляет несколько страниц текущего файла
- **THEN** операция исполняется без запроса подтверждения и без ограничения текущим выделением при соблюдении Plugin API

### Requirement: Контроль пользователя
UI MUST показывать состояние соединения, доступное имя документа, Full-document / YOLO, состояние записи, текущую операцию и последние ошибки. Пользователь MUST иметь управление отключением записи, остановкой очереди и разрывом соединения.

#### Scenario: Пользователь отключил запись
- **WHEN** пользователь отключает запись во время пакета
- **THEN** дальнейшие изменяющие шаги и ожидающая запись прекращаются на ближайшей доступной границе; чтение остаётся доступным, применённые изменения перечислены

#### Scenario: Закрытие плагина
- **WHEN** пользователь закрывает плагин или разрывает соединение
- **THEN** новые команды к документу не исполняются; ранее применённое не откатывается, а неподтверждённый результат не объявляется успешным
