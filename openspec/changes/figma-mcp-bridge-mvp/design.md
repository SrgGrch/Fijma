# Технический проект Fijma MVP

## Context

Мотивация и охват: [proposal.md](proposal.md). Исходные решения: [дизайн v0.2](../../../figma-mcp-design-v0.2.md), D1–D5. Репозиторий пока содержит только документы и OpenSpec; совместимость с существующим кодом не требуется.

Все требования находятся в [specs](specs/). Ниже — предлагаемые технические решения для их реализации. Выбор языка, SDK и версий зависимостей фиксируется в задаче 1.1 после проверки совместимости; он не меняет внешний контракт.

## Goals / Non-Goals

**Goals:** единый декларативный контракт на границах MCP → мост → UI → выполняющая часть; проверяемая адресация команд; минимальное состояние сервера; восстановление после сбоев без дубликатов.

**Non-Goals:** независимая копия макета, универсальный интерпретатор Plugin API, транзакционная изоляция, долговечная очередь записи и автоматическая компенсация изменений. Продуктовые исключения перечислены в proposal.

## Decisions

### 1. Один процесс сервера и три границы доверия

MCP-адаптер и WebSocket-мост работают в одном процессе, с одной очередью записи. UI плагина обеспечивает сеть и отображение; только выполняющая часть обращается к живому дереву и изменяет его. Схемы команд общие по смыслу и проверяются сервером и выполняющей частью; UI проверяет сообщения, но не дублирует правила редактирования.

Предлагаемая структура при реализации: `server/` — MCP и соединение; `plugin/` — main, UI и manifest; `shared/` — схемы протокола; `tests/` — контрактные фикстуры и проверки без Figma. Это каталоги одного проекта, а не отдельные сервисы. Альтернатива с отдельным процессом моста добавляет ненужные развёртывание и синхронизацию.

Manifest ограничивает editorType значением figma, использует documentAccess dynamic-page и разрешает только проверенный loopback endpoint. Все сообщения stdio соответствуют согласованной версии MCP; диагностика идёт в stderr. Версия MCP и версия внутреннего протокола фиксируются независимо. Нельзя механически использовать пример ответа новой спецификации, если клиент согласовал более старую.

### 2. Сопряжение и состояние соединения

Сервер слушает конкретный loopback IP и порт, без wildcard bind. Случайный ключ сохраняется между запусками сервера в локальном файле с правами только текущего пользователя. Пользователь вводит его в UI при первом сопряжении; после успешного согласования плагин сохраняет ключ в локальном `figma.clientStorage` и использует его при следующих запусках. Ключ сервера не удаляется при штатном завершении. Диагностические пробы используют отдельные временные ключи. Это подключение инструмента, а не подтверждение каждой правки. Секрет не передаётся в URL, MCP-контекст, stdout/stderr или журналы и не сохраняется внутри документа Figma.

UI посылает секрет первым аутентификационным сообщением. После транспортного обрыва UI восстанавливает соединение с задержкой 1–15 секунд только в видимой вкладке; ручное отключение приостанавливает восстановление до явного подключения или нового запуска. «Забыть» удаляет сохранённую копию ключа в плагине. Неверный ключ удаляется; занятая сессия и ошибки протокола прекращают автоматические попытки. Постоянное сопряжение не сохраняет разрешение записи, поколение, очередь или идентичность документа. Для полного отзыва ключа пользователь останавливает сервер и удаляет его файл ключа перед новым запуском. До проверки секрета допустимы только ограниченные по размеру сообщения сопряжения; действуют лимит попыток и таймаут. Origin проверяется с учётом реального iframe, но не заменяет секрет. Наличие доступа к компьютеру само по себе не является удалённой моделью аутентификации.

Состояния моста: disconnected → pairing → ready; несовместимость даёт incompatible, отсутствие подтверждённой привязки — rebinding, разрыв — disconnected. Флаг writeEnabled независим от состояния соединения. Второе соединение получает SESSION_BUSY и не вытесняет первое. UI-остановка имеет приоритет над обычной очередью и проверяется между ограниченными участками работы.

### 3. Идентичность сессии

Выполняющая часть создаёт sessionId на запуск плагина. Каждое принятое WebSocket-соединение получает новое connectionGeneration, известное всем звеньям. figma.fileKey необязателен, имя файла служит только отображению. Узлы, cursors и ресурсы связаны с sessionId.

После переподключения того же main sessionId сохраняется, поколение меняется; после перезапуска main создаётся новая сессия. Агент получает новый контекст перед следующей записью. Старые очереди не переносятся. Статус неподтверждённой операции можно запросить в живой сессии через новое соединение с указанием её исходного ID.

Смена документа аннулирует привязку. Конкретные события и закрытие/сохранение main при переключении вкладок проверяются задачей 1.2. До установления надёжной границы документы не считаются взаимозаменяемыми; невозможность обеспечить границу блокирует готовность этого транспорта, а не разрешает маршрутизацию по имени.

### 4. Поверхность MCP

Имена ниже — предлагаемый стабильный каталог MVP. Полные JSON Schema и совпадающие с ними примеры создаются в задаче 2.1; таблица определяет обязательную семантику. `scope` во всех инструментах документа — `{sessionId, connectionGeneration}`. Новая операция получает operationId; повтор записи использует прежний ID и тот же payload.

| Инструмент | Параметры сверх scope | Результат |
|---|---|---|
| `figma_get_context` | Нет; доступен без scope и плагина | Состояние, сессия, поколение, documentLabel, страницы, currentPageId, selection, writeEnabled, capabilities, limits |
| `figma_get_tree` | rootId, depth, limit, cursor? | Упорядоченные узлы, truncated, nextCursor? |
| `figma_find_nodes` | rootId или область документа, name?, types?, limit, cursor? | Совпадения, сведения страницы, truncated, nextCursor? |
| `figma_get_nodes` | nodeIds, fields | Запрошенные свойства, признаки mixed, ошибки отсутствующих узлов |
| `figma_get_local_resources` | kind components/styles/collections/variables, ids?, fields, limit, cursor? | Типизированные локальные ресурсы, modes/aliases/bindings по проекции, nextCursor? |
| `figma_navigate` | pageId?, nodeIds, select, reveal | Текущая страница, фактическое выделение |
| `figma_apply_batch` | operationId, steps | Итог операции, результаты всех шагов и фактические изменения |
| `figma_get_operation` | operationId | Известный статус/результат либо unknown; чтение статуса не повторяет запись |
| `figma_cancel_operation` | operationId | Запрос остановки и известное состояние, а не обещание немедленного отката |
| `figma_export_node` | nodeId, format PNG/SVG, scale? | Структурные метаданные и содержимое/ресурс экспорта |

Навигация меняет только текущую страницу, выделение и viewport и проходит проверку сессии. Экспорт является отдельным вызовом: успешная запись не означает успешной визуальной проверки. Ресурсы дизайн-системы читаются отдельным типизированным запросом, поскольку коллекции, стили и переменные не являются scene nodes.

### 5. Внутренние сообщения

После аутентификации `hello`/`welcome` согласуют protocolVersion, sessionId, connectionGeneration, capabilities, limits и writeEnabled. Затем допускаются `command`, `ack`, `result`, `getOperation`, `cancel` и сообщения изменения состояния. Неизвестные поля отклоняются, если они не объявлены согласованной схемой.

Конверт команды: operationId, sessionId, connectionGeneration, command, params. Для записи command равен applyBatch, params содержит steps. Каждый шаг содержит stepId, op и типизированные параметры; `expected` обязателен для изменения/удаления существующего объекта. Созданный ранее в пакете объект уже проверяется по известному результату шага.

Ссылка на существующий узел: `{nodeId}`; ссылка на результат предыдущего шага: `{stepId, output}`. Разрешённые output объявлены для каждого op, например nodeId, styleId, collectionId, modeId, variableId. Ссылка на стиль не может стать parent узла. До записи проверяется структура всего пакета, а доступность текущего состояния и API — перед каждым шагом.

| Группа операций | Декларативные действия и обязательные данные |
|---|---|
| Структура | createPage(name), renamePage(pageId,name), clonePage(pageId,name?), movePage(pageId,index), deletePage(pageId), createNode(type,parent,properties), updateNode(target,patch), cloneNode(target,parent,index?), deleteNode(target), moveNode(target,parent,index), groupNodes(targets,parent), ungroupNode(target) |
| Компоновка | setGeometry(target,position/size/rotation), setConstraints(target,value), setAutoLayout(target,layout), setLayoutSizing(target,sizing) |
| Текст | createText(parent,characters,font,typography), setText(target,characters), replaceTextRange(target,start,end,text,insertionFormatting), formatTextRange(target,start,end,format) |
| Графика | setAppearance(target,appearance), importImage(data,mimeType,parent,placement), importSvg(svg,parent), booleanNodes(kind,targets,parent) |
| Компоненты | createComponent(parent,properties), componentFromNode(target), combineVariants(targets,parent), setComponentProperties(target,definitions), createInstance(componentId,parent), setInstanceProperties(target,values), swapVariant(target,componentId), detachInstance(target) |
| Стили | createStyle(type,name,value), updateStyle(styleId,patch), applyStyle(target,property,styleId), unbindStyle(target,property), deleteStyle(styleId) |
| Переменные | createCollection(name), updateCollection(collectionId,patch), deleteCollection(collectionId), createMode(collectionId,name), renameMode(collectionId,modeId,name), deleteMode(collectionId,modeId), createVariable(collectionId,name,type), updateVariable(variableId,patch), deleteVariable(variableId), setVariableValue(variableId,modeId,value), setVariableAlias(variableId,modeId,targetVariableId), bindVariable(target,property,variableId), unbindVariable(target,property), setNodeMode(target,collectionId,modeId) |

`properties`, `patch`, `layout`, `format` и прочие объекты — конечные наборы типизированных полей для конкретного типа, а не произвольные пути Plugin API. Снятие блокировки, стиля или variable binding допускается только явным полем/операцией. Результат обновления никогда не скрывает detach. Для чувствительных общих ресурсов expected относится к ресурсу и меняемым связям, а не только к одному scene node.

Общие типы узлов не создают обходных путей: createNode с type TEXT использует те же проверки шрифтов, что createText; текстовые поля updateNode проходят правила text-editing. Типы COMPONENT/INSTANCE и ресурсы дизайн-системы создаются только предметными операциями. Страницы клонируются и перемещаются отдельными командами, чтобы не смешивать DocumentNode с контейнерами scene nodes.

Геометрия задаётся относительно родителя; при reparent координаты также трактуются в новом родителе и фактические значения возвращаются после компоновки. Индекс — позиция среди детей нового родителя после исключения перемещаемого узла. Несовместимые Auto Layout параметры отклоняются без тихого изменения модели. Диапазоны текста используют [start,end) в UTF-16; нельзя делить суррогатную пару.

### 6. Результаты и ошибки

Общий результат: operationId, sessionId, connectionGeneration, status, steps, affectedNodeIds, affectedResourceIds, warnings, error?. Шаг содержит stepId, status, outputs, appliedChanges и error?. Невыполненные шаги имеют skipped; это состояние шага, а не операции. appliedChanges включает известные изменения внутри упавшего шага.

Для ошибок: code, message, failedStep?, details без секретов и recoveryAction. MCP ошибки исполнения имеют isError; ошибки обнаружения самого инструмента остаются ошибками протокола. structuredContent и текстовое представление одного результата должны совпадать и соответствовать outputSchema. Поля конверта MCP зависят от согласованной версии.

| Код | Действие агента |
|---|---|
| NOT_CONNECTED, AUTH_FAILED | Восстановить локальное подключение; секрет не получать через инструмент |
| SESSION_BUSY | Устранить второе подключение без вытеснения активного |
| PROTOCOL_MISMATCH | Установить совместимые версии сервера и плагина |
| SESSION_EXPIRED, DOCUMENT_MISMATCH | Получить контекст; не переносить старые команды автоматически |
| INVALID_ARGUMENT, INVALID_CURSOR | Исправить параметры или начать чтение заново |
| NODE_NOT_FOUND | Перечитать область, не искать замену по имени автоматически |
| CAPABILITY_UNAVAILABLE, FONT_UNAVAILABLE | Устранить явную причину либо выбрать поддерживаемую операцию |
| CONFLICT | Перечитать живое состояние и заново сформировать изменение |
| OPERATION_ID_CONFLICT, OPERATION_EXPIRED | Не повторять этот ID как новую запись; проверить результат |
| RESOURCE_LIMIT, RESOURCE_EXPIRED | Уменьшить объём либо повторно запросить чтение/экспорт |
| WRITE_DISABLED | Дождаться явного включения записи пользователем |
| FIGMA_API_ERROR | Сообщить ограничение API с результатом уже сделанного |
| OUTCOME_UNKNOWN | Запросить статус и перечитать документ без слепого повтора |

`partially_applied` и `unknown` описываются статусами, не маскируются обычным failed. Частичная запись/неопределённость дают isError, сохраняя полезные данные в результате.

### 7. Очередь, конфликты и повторы

Основные переходы: queued → running → succeeded/failed/partially_applied/cancelled/unknown; queued также может перейти в cancelled/failed. unknown означает недостаток доказательств и может уточняться после запроса живого журнала. Если запись ещё не была передана плагину, разрыв не считается доказательством её применения.

Сервер сериализует запись, а main повторно проверяет expected по живым свойствам непосредственно перед действием, в том числе после await загрузки страницы или шрифтов. Это уменьшает окно конфликтов, но не создаёт блокировки для соавторов. Массивы, порядок детей и связи сравниваются как значимые данные, а не только имя узла.

Плагин хранит результаты и fingerprint запроса в ограниченном журнале живой сессии. Fingerprint включает семантику записи и expected, исключая поколение транспортного соединения. Повтор в новом поколении той же сессии допустим только как выяснение/возврат прежнего результата, а не автоматическое исполнение неподтверждённой записи.

Для безопасного истечения журнала operationId должен иметь проверяемое время создания: предлагается формат UUIDv7 с окном допустимого возраста и согласованным допуском часов. Истёкший ID отклоняется до исполнения даже после удаления его результата. Внутри окна записи не вытесняются: при заполнении журнала новые записи отклоняются RESOURCE_LIMIT. Переиспользование ID с изменёнными параметрами запрещено. Это ограниченная гарантия живой сессии, а не persistent exactly-once.

Шаги пакета исполняются до первой ошибки. Отмена проверяется до следующего шага и между ограниченными порциями длительной работы. На границах логических пакетов используется commitUndo; глобальный Undo при ошибках не вызывается. Компенсации и режим continue-on-error в MVP не добавляются.

### 8. Чтение, ресурсы и журнал

Страницы загружаются по необходимости. Дерево и поиск ограничены depth, maxNodes и maxResponseBytes; cursor привязан к параметрам, сессии и наблюдаемому состоянию области. При изменении, нарушающем обход, возвращается INVALID_CURSOR. События документа инвалидируют кэш, но не являются глобальной транзакционной версией.

Чтение возвращает типизированные значения, `mixed` и связи отдельно от вычисленных значений. Шрифты загружаются до изменений текста; частичная замена использует явное оформление вставки и сохраняет свойства сохранившихся символов. Импорт принимает байты/SVG, а не URL или локальный путь; проверка SVG запрещает скрипты, внешние ссылки и чрезмерный объём до передачи Figma.

Небольшой PNG выдаётся поддерживаемым MCP image block. Более крупный результат и SVG — ресурс, связанный с сессией, MIME и сроком жизни; выбранный способ проверяется с реальным клиентом. URI ресурса непрозрачен и не является файловым путём. Для MVP не нужен отдельный HTTP download endpoint. Если клиент не умеет читать ресурсы, явно возвращается ограничение; нельзя объявлять визуальную проверку выполненной по структурным данным.

Контекст публикует maxMessageBytes, maxBatchSteps, maxQueuedOperations, maxDepth, maxNodes, maxResponseBytes, maxImportBytes, maxExportPixels, maxExportBytes, operationTimeout, dedupTtl, maxJournalEntries, resourceTtl и допустимый clockSkew. Значения определяются проверками 1.2–1.6 и затем фиксируются в конфигурации и граничных тестах. До этого числа не являются обещанием производительности. Таймаут переданной записи даёт unknown до выяснения результата.

Журнал содержит только идентификаторы, тип, длительность и статус; текст, изображения, полный payload и секреты исключены. Включаемая пользователем расширенная диагностика также редактирует секреты и имеет срок хранения. Содержимое слоя никогда не используется как настройка соединения.

| §13: дополнительные случаи | document-reading, scene-editing, local-design-system | Пустой файл, mixed fonts, скрытые/locked слои, instance constraints, внешняя библиотека |
| §14: непроверенные свойства платформы | result-verification | Эксперименты 1.2–1.6 и запись окружения |

### 10. Источники технических ограничений

Через Context7 сверены официальные материалы: [среда main/UI](https://developers.figma.com/docs/plugins/how-plugins-run/), [manifest и dynamic-page](https://developers.figma.com/docs/plugins/manifest/), [работа с текстом](https://developers.figma.com/docs/plugins/working-with-text/), [commitUndo](https://developers.figma.com/docs/plugins/api/properties/figma-commitundo/), [MCP stdio](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio), [MCP tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools). Остальные источники Plugin API перечислены в исходном дизайне; их методы и типы сверяются при реализации соответствующей группы операций. Документация не заменяет Desktop-эксперименты.

## Risks / Trade-offs

- [WebSocket/manifest может отличаться на целевой ОС] → сначала реальное соединение, затем основной код; wildcard network access не является обходным решением.
- [Переключение вкладок не даёт ожидаемых событий] → проверить жизненный цикл main и при сомнении блокировать запись; не подменять сессию file name.
- [Ручные правки между проверкой и записью] → повторная проверка после асинхронных зависимостей; явно ограниченная оптимистическая гарантия.
- [Остановка не прерывает синхронный Plugin API] → ограничивать шаги/объём и показывать фактическую задержку остановки.
- [Недоступные режимы переменных/шрифты] → runtime capabilities и ошибки без замены модели документа.
- [Результат применён, но потерян] → живой журнал, статус, чтение и unknown; без автоматического повтора или Undo.
- [Экспорт слишком велик или клиент его не показывает] → явные лимиты и проверенный способ передачи; структурная проверка обязательна.
- [YOLO допускает разрушительные правки] → явный статус полного доступа и stop; для ручной приёмки использовать тестовый файл. Новые approval-шаги не добавляются.

## Migration Plan

Миграции данных нет. Развёртывание начинается с локальной сборки сервера и плагина, импорта manifest в Desktop и настройки stdio-клиента. Проверки транспорта выполняются в тестовом файле. Затем поэтапно включаются чтение, основное редактирование и дизайн-система; все три этапа нужны для полного MVP.

Откат инструмента: остановить сервер/плагин и вернуть прежнюю сборку. Изменения документа при этом не откатываются; история Figma и копия тестового файла используются пользователем отдельно. Инструкция запуска должна объяснять это и передачу данных выбранному поставщику модели.

## Open Questions

После экспериментов фиксируются конкретные версии SDK/MCP-клиента, loopback endpoint, значения лимитов, фактическая задержка stop и удобный поддерживаемый способ выдачи экспорта. Это параметры реализации внутри выбранной архитектуры. Отрицательный результат проверки границ сессии, транспорта или Undo регистрируется как блокер соответствующего критерия приёмки; изменение D1–D5 требует отдельного решения, а не скрытого расширения MVP.
