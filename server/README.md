# Запуск локального сервера

Из корня: `npm ci`, `npm run build`, `npm start`. Для stdio-клиента команда — `node`, аргумент — полный путь `G:\Projects\AI\Figma-plugin-mcp\dist\server\index.js`. stdout занят MCP; путь файла сопряжения выводится только в stderr. Клиент должен запускать один процесс сервера.

Сервер слушает только 127.0.0.1:55263. Переменная окружения FIGMA_MCP_PORT позволяет выбрать другой порт; 0 используется автотестом для свободного временного порта. Если порт занят, запуск завершается без вывода секрета. Порт в manifest должен совпадать с выбранным, когда сетевой UI будет подключён.

Случайный секрет процесса — в pairing-secret.txt внутри нового временного каталога. На Windows перед записью секрета каталог лишается наследования ACL и получает доступ только SID текущего пользователя; на других ОС каталог mkdtemp закрыт для остальных, файл имеет mode 600. При невозможности ограничить доступ запуск прекращается. В штатном завершении stdin/SIGINT/SIGTERM файл удаляется; аварийное убийство процесса может оставить защищённый файл со старым, более не действующим секретом.

Первое WebSocket-сообщение: `{type:"pair",secret:"<значение из файла>"}`. Секрет не помещается в URL, контекст или логи. Неверный секрет закрывает соединение с AUTH_FAILED. Повторный плагин после успешного сопряжения получает SESSION_BUSY, не вытесняя первый. До сопряжения — максимум 4 соединения, 60 попыток подключения в минуту и 5 секунд ожидания; bootstrap-сообщение ограничено 1024 байтами. Origin ограничен отсутствующим, null и https://www.figma.com; он не заменяет секрет. Совместимость этих ограничений с настоящим iframe рабочего UI ещё предстоит проверить.

После paired сервер принимает строго проверенный hello (версия, sessionId, capabilities, limits, writeEnabled), возвращает welcome с новым connectionGeneration. Ожидание hello ограничено 5 секундами. Повторное соединение сохраняет sessionId, если main его предъявил, но всегда получает новое поколение. После закрытия соединения привязка удаляется. Контекст и чтение документа проходят через UI/main; MCP сообщает ready после успешного чтения контекста. Неподключённые инструменты дают CAPABILITY_UNAVAILABLE, запись недоступна. Сопряжение не означает готовность документа и не разрешает запись. Пользовательский UI и транспортная проверка 1.2 ещё не завершены; этапы 3.2–3.4 остаются открытыми.

Рабочий UI сопряжения собран в `G:\Projects\AI\Figma-plugin-mcp\dist\plugin\manifest.json`. Ввод секрета очищается после подключения, секрет не сохраняется в документе или localStorage. UI передаёт hello main в listener и welcome обратно, отображает имя документа и предоставляет доступную с клавиатуры кнопку отключения. Статус записи выключен. Контекст перечитывается из main при каждом запросе, обход загружает только нужные страницы. Cursor связан с областью и ревизией страницы. Рабочий потолок дерева сейчас 1000 узлов/32768 байт массива при глубине до 8, транспорт — 65536 байт; это предварительные защитные пределы. Bootstrap-лимиты предварительные и не означают поддержку перечисленных объёмов команд. manifest ограничен ws://localhost:55263; подключение этой сборки в Desktop ещё не проверялось. Старый диагностический сервер session-probe на том же порту нужно остановить до запуска рабочего сервера.

Проверки одним батчем: `npm test`. Они отделены от ручной Desktop-приёмки. Новые ручные проверки следует объединять в один сценарий после подключения маршрутизации, а не повторять большой нагрузочный стенд после каждого изменения.

Доступны `figma_get_tree` и `figma_find_nodes`. Оба требуют `scope` из свежего контекста; чтение не меняет страницу, выделение или viewport. Пример дерева: `{"scope":{"sessionId":"…","connectionGeneration":1},"rootId":"0:1","depth":3,"limit":100}`. Результат — упорядоченный обход с `nodeId`, `name`, `type`, `depth`, `truncated` и необязательным `nextCursor`.

Пример поиска по документу: `{"scope":{"sessionId":"…","connectionGeneration":1},"document":true,"name":"Button","types":["FRAME"],"limit":100}`. Вместо `document` можно указать `rootId` страницы или поддерева. `name` — подстрока с учётом регистра, `types` — точные типы Figma. Результаты содержат также `pageId`. Поиск загружает страницы последовательно, не вызывает `loadAllPages`, и за запрос обходит не больше согласованного maxNodes; поэтому даже пустая страница результатов может иметь продолжение. На глубине maxDepth поиск сохраняет границу обхода в cursor и продолжает с неё следующим запросом, включая более глубокие узлы.

Для продолжения повторите те же параметры с `cursor: nextCursor`. Cursor одноразовый и ограничен сроком; изменение параметров, сессии, поколения, списка страниц или наблюдаемого содержимого возвращает `INVALID_CURSOR`. Число сохранённых рамок обхода ограничено maxNodes; при превышении возвращается `RESOURCE_LIMIT`, без пропуска веток. События не делают чтение атомарным снимком; после ошибки начните обход заново. В дереве `truncated` сообщает и о продолжении, и о достижении запрошенной глубины. Действуют предварительные maxDepth=8, maxNodes=1000 и maxResponseBytes=32768; часть бюджета байтов зарезервирована под оболочку результата. Проверки в реальном Figma Desktop и измерение пределов 1.6 ещё предстоят.

Чтение узлов: `{"scope":{"sessionId":"…","connectionGeneration":1},"nodeIds":["1:1"],"fields":["name","visible","locked","fontName","textSegments","fillStyleId","boundVariables","mainComponent"]}`. Каждый узел возвращает `properties`, списки `mixed` и `unavailable`; удалённый nodeId получает отдельный `NODE_NOT_FOUND`. `textSegments` возвращает диапазоны и их форматирование; `mainComponent` содержит id, key и признак внешней библиотеки remote. Неподдерживаемая разновидность значения целиком отмечается как unavailable, не подменяется усечённой копией.

Чтение локальных ресурсов: `{"scope":{"sessionId":"…","connectionGeneration":1},"kind":"variables","fields":["name","type","collectionId","valuesByMode"],"limit":100}`. Доступны kinds `components`, `styles`, `collections`, `variables`; `ids` необязателен. Стили и переменные читаются через асинхронные локальные API Figma; компоненты ищутся на страницах постепенно. Повторяйте запрос с `nextCursor`, пока он есть; совпадения компонентов возвращаются не более чем по одному за запрос. Для проверки неизменности локальных ресурсов сохранённая проекция ограничена maxMessageBytes: при превышении возвращается `RESOURCE_LIMIT`. Эти чтения также ещё не проверены в Desktop.

Явный переход: `{"scope":{"sessionId":"…","connectionGeneration":1},"nodeIds":["1:1"],"select":true,"reveal":true}`. Узлы должны существовать на одной странице; при необходимости она загружается и открывается. Опциональный `pageId` должен совпадать с их страницей; с пустым `nodeIds` можно открыть страницу или очистить выделение через `select:true`. `select` и `reveal` отдельно управляют выделением и viewport; ответ содержит фактические `currentPageId` и `selection`. Остальные чтения не переключают страницу, выделение или viewport. Продолжения обхода ограничены сессией и поколением, а наблюдаемые изменения страницы инвалидируют соответствующие cursor; проекции узлов перечитываются из Figma. Интеграционный тест с имитацией Figma проверяет, что подготовленные callbacks проверки перед записью повторно читают имя и детей и возвращают CONFLICT при ручной правке. Эти callbacks ещё не подключены к записи в main; проверка в Desktop остаётся открытой.
