# Запуск локального сервера

При MCP-инициализации сервер передаёт агенту инструкции подключения: если контекст сообщает disconnected или инструмент возвращает NOT_CONNECTED, агент должен сразу показать команду PowerShell для копирования ключа и шаги «открыть файл → запустить плагин → вставить ключ → Подключиться и запомнить». Команда использует фактический путь pairing-файла, включая FIGMA_MCP_PAIRING_DIR. Сам ключ в инструкции не передаётся, агент не должен читать его или просить прислать в чат. При SESSION_BUSY повторное сопряжение не предлагается. Следование инструкциям зависит от MCP-клиента и агента.

Актуальное продолжение реализации и приёмки: [графика и локальная дизайн-система](../docs/milestone-4.md).

Пошаговая инструкция импорта manifest, настройки stdio-клиента, сопряжения, candidate и остановки: [запуск в Desktop](../docs/launch.md). Текущие результаты реальных проверок: [отчёт](../docs/milestone-4.md).

Из корня: `npm ci`, `npm run build`, `npm start`. Для stdio-клиента команда — `node`, аргумент — полный путь `G:\Projects\AI\Figma-plugin-mcp\dist\server\index.js`. stdout занят MCP; путь файла сопряжения выводится только в stderr. Каждый клиент запускает свой stdio-адаптер; адаптеры используют один общий процесс моста. Инициализация доступна всем, работа с документом — одному владельцу; остальные получают SESSION_BUSY.

Сервер слушает только 127.0.0.1:55263. Переменная окружения FIGMA_MCP_PORT меняет порт сервера; 0 используется автотестом для свободного временного порта. Если порт занят совместимым общим мостом, адаптер подключается к нему. Если его держит старый или посторонний сервер, запуск завершается с диагностикой без завершения владельца порта. Для Desktop используйте стандартный порт: смена порта требует согласованного изменения endpoint UI и manifest с пересборкой.

Случайный ключ сохраняется между запусками в `.figma-mcp-bridge/pairing-secret.txt` домашней папки пользователя (переопределяется `FIGMA_MCP_PAIRING_DIR`). На Windows каталог и файл получают защищённый ACL только для SID текущего пользователя; на POSIX — 700/600. Существующий ключ проверяется и переиспользуется. При невозможности ограничить доступ или повреждённом файле запуск прекращается без замены ключа. При завершении ключ сохраняется. Диагностический сервер продолжает использовать отдельный временный ключ, который удаляется при штатном завершении.

Первое WebSocket-сообщение: `{type:"pair",secret:"<значение из файла>"}`. Секрет не помещается в URL, контекст или логи. Неверный секрет закрывает соединение с AUTH_FAILED. Повторный плагин после успешного сопряжения получает SESSION_BUSY, не вытесняя первый. До сопряжения — максимум 4 соединения, 60 попыток подключения в минуту и 5 секунд ожидания; bootstrap-сообщение ограничено 1024 байтами. Origin ограничен отсутствующим, null и https://www.figma.com; он не заменяет секрет. Сопряжение candidate, неверный секрет и второй плагин проверены в Desktop; окружение и результаты приведены в отчёте.

После paired сервер принимает строго проверенный hello (версия, sessionId, capabilities, limits, writeEnabled), возвращает welcome с новым connectionGeneration. Ожидание hello ограничено 5 секундами. Повторное соединение сохраняет sessionId, если main его предъявил, но всегда получает новое поколение. Поколения непрозрачны и после перезапуска сервера могут уменьшаться. После закрытия соединения привязка удаляется. Контекст и чтение документа проходят через UI/main; MCP сообщает ready после успешного чтения контекста. Сопряжение само по себе не разрешает запись: пользователь включает её в UI. Граница документа проверена в Desktop при переключении файлов, возврате и перезапуске плагина.

Рабочий UI сопряжения собран в `G:\Projects\AI\Figma-plugin-mcp\dist\plugin\manifest.json`. Ввод секрета очищается после подключения, после успешного согласования ключ сохраняется через `figma.clientStorage`, отдельно от документа. При запуске и после обрыва UI автоматически подключается к прежнему серверу. «Отключить» приостанавливает повторные попытки, «Забыть» удаляет копию ключа из плагина. Неверный ключ очищается; `SESSION_BUSY` не вытесняет другое соединение и останавливает повторные попытки. UI передаёт hello main в listener и welcome обратно, отображает имя документа и предоставляет доступное с клавиатуры управление записью и соединением. При подключении запись выключена до явного включения. Контекст перечитывается из main при каждом запросе, обход загружает только нужные страницы. Cursor связан с областью и ревизией страницы. Рабочий потолок дерева сейчас 1000 узлов/32768 байт массива при глубине до 8, транспорт — 65536 байт; это предварительные защитные пределы. Bootstrap-лимиты предварительные и не означают поддержку перечисленных объёмов команд. manifest ограничен ws://localhost:55263. Старый диагностический сервер session-probe на том же порту нужно остановить до запуска рабочего сервера.

Проверки одним батчем: `npm test`. Они отделены от ручной Desktop-приёмки. Новые ручные проверки следует объединять в один сценарий после подключения маршрутизации, а не повторять большой нагрузочный стенд после каждого изменения.

Доступны `figma_get_tree` и `figma_find_nodes`. Оба требуют `scope` из свежего контекста; чтение не меняет страницу, выделение или viewport. Пример дерева: `{"scope":{"sessionId":"…","connectionGeneration":1},"rootId":"0:1","depth":3,"limit":100}`. Результат — упорядоченный обход с `nodeId`, `name`, `type`, `depth`, `truncated` и необязательным `nextCursor`.

Пример поиска по документу: `{"scope":{"sessionId":"…","connectionGeneration":1},"document":true,"name":"Button","types":["FRAME"],"limit":100}`. Вместо `document` можно указать `rootId` страницы или поддерева. `name` — подстрока с учётом регистра, `types` — точные типы Figma. Результаты содержат также `pageId`. Поиск загружает страницы последовательно, не вызывает `loadAllPages`, и за запрос обходит не больше согласованного maxNodes; поэтому даже пустая страница результатов может иметь продолжение. На глубине maxDepth поиск сохраняет границу обхода в cursor и продолжает с неё следующим запросом, включая более глубокие узлы.

Для продолжения повторите те же параметры с `cursor: nextCursor`. Cursor одноразовый и ограничен сроком; изменение параметров, сессии, поколения, списка страниц или наблюдаемого содержимого возвращает `INVALID_CURSOR`. Число сохранённых рамок обхода ограничено maxNodes; при превышении возвращается `RESOURCE_LIMIT`, без пропуска веток. События не делают чтение атомарным снимком; после ошибки начните обход заново. В дереве `truncated` сообщает и о продолжении, и о достижении запрошенной глубины. Действуют предварительные maxDepth=8, maxNodes=1000 и maxResponseBytes=32768; часть бюджета байтов зарезервирована под оболочку результата. Desktop-измерения и их ограничения описаны в [отчёте](../docs/milestone-4.md).

Чтение узлов: `{"scope":{"sessionId":"…","connectionGeneration":1},"nodeIds":["1:1"],"fields":["name","visible","locked","fontName","textSegments","fillStyleId","boundVariables","mainComponent"]}`. Каждый узел возвращает `properties`, списки `mixed` и `unavailable`; удалённый nodeId получает отдельный `NODE_NOT_FOUND`. `textSegments` возвращает диапазоны и их форматирование; `mainComponent` содержит id, key и признак внешней библиотеки remote. Неподдерживаемая разновидность значения целиком отмечается как unavailable, не подменяется усечённой копией.

Чтение локальных ресурсов: `{"scope":{"sessionId":"…","connectionGeneration":1},"kind":"variables","fields":["name","type","collectionId","valuesByMode"],"limit":100}`. Доступны kinds `components`, `styles`, `collections`, `variables`; `ids` необязателен. Стили и переменные читаются через асинхронные локальные API Figma; компоненты ищутся на страницах постепенно. Повторяйте запрос с `nextCursor`, пока он есть; совпадения компонентов возвращаются не более чем по одному за запрос. Для проверки неизменности локальных ресурсов сохранённая проекция ограничена maxMessageBytes: при превышении возвращается `RESOURCE_LIMIT`. Чтение локального стиля и переменной проверено в Desktop; детали и оставшиеся ограничения приведены в отчёте.

Явный переход: `{"scope":{"sessionId":"…","connectionGeneration":1},"nodeIds":["1:1"],"select":true,"reveal":true}`. Узлы должны существовать на одной странице; при необходимости она загружается и открывается. Опциональный `pageId` должен совпадать с их страницей; с пустым `nodeIds` можно открыть страницу или очистить выделение через `select:true`. `select` и `reveal` отдельно управляют выделением и viewport; ответ содержит фактические `currentPageId` и `selection`. Остальные чтения не переключают страницу, выделение или viewport. Продолжения обхода ограничены сессией и поколением, а наблюдаемые изменения страницы инвалидируют соответствующие cursor; проекции узлов перечитываются из Figma. Исполнитель перечитывает заданные предусловия узлов и ресурсов после загрузки зависимостей; конфликт возвращает CONFLICT. Основная и candidate-сборки используют один runtime записи.

Экспорт: `{"scope":{"sessionId":"…","connectionGeneration":1},"nodeId":"1:1","format":"PNG","scale":2}` или `{"scope":{"sessionId":"…","connectionGeneration":1},"nodeId":"1:1","format":"SVG"}`. PNG возвращает фактические размеры из заголовка, MIME и размер; до 12 288 байт включительно он также передаётся MCP image block, более крупный — ресурсом. SVG всегда возвращается ресурсом; `scale` для SVG допускается только 1. Изображение не уменьшается автоматически: превышение согласованных пиксельного или байтового пределов возвращает `RESOURCE_LIMIT`. PNG с недоступными границами отклоняется как `CAPABILITY_UNAVAILABLE`. Клиенту без поддержки image blocks требуется поддержка ресурсов для крупных PNG и SVG; сама успешная передача не подтверждает визуальную проверку.

Ресурс `figma-resource://export/<непрозрачный токен>` читается стандартным MCP `resources/read` без пути к файлу и без sessionId в запросе: сервер использует текущую авторизованную привязку. `expiresAt` — верхняя граница, а не обещание доступности: ресурсы немедленно удаляются при обрыве соединения, включая повторное подключение той же сессии, и при закрытии сервера. В памяти хранится не более 16 ресурсов и четырёх согласованных `maxExportBytes` суммарно; истёкший или недоступный ресурс возвращает `RESOURCE_EXPIRED` с предложением повторить экспорт. Данные экспорта передаются между main и сервером порциями до 12 288 байт, с уменьшением порции при более строгом согласованном `maxMessageBytes`. После таймаута сервер временно отклоняет новые запросы, пока не придёт окончание старого ответа или не истечёт ограниченный срок ожидания; поздний ответ не сопоставляется с новой командой. PNG image block и SVG resource проверены через candidate в Desktop; получение изображения напрямую моделью через MCP этим не доказано.

Общий процесс запускается адаптером автоматически, независимо от его stdio. Локальный IPC использует взаимную HMAC-аутентификацию и отдельный SDK transport на клиента. Закрытие владельца сбрасывает привязку плагина до передачи управления. Для остановки: `node dist/server/index.js --stop-bridge`; используйте её также после обновления сборки. `FIGMA_MCP_PORT=0` сохраняет прежний изолированный режим тестов.
