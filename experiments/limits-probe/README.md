# Стенд задачи 1.6

Из корня: `npx esbuild experiments/limits-probe/main.ts --bundle --target=es2017 --outfile=experiments/limits-probe/main.js`.
Проверка общего обхода: `node tests/read-tree.mjs`.

Импортируйте manifest.json из этого каталога в Figma Desktop, запустите в отдельном тестовом файле и нажмите «Измерить». Сохраните отчёт без остановки. Повторите и нажмите «Остановить» во время создания фикстуры; повторите остановку во время PNG-экспорта. Запишите ОС, Desktop, размер файла и отчёты всех запусков.

Стенд создаёт временный фрейм с 5000 прямоугольников, читает не более 1000 узлов и 256 KiB JSON массива, глубина до 8, уступает управление каждые 50 узлов. Он загружает только текущую страницу, не переключает её и не меняет выделение. Фрейм удаляется в finally, ошибки очистки видны в отчёте. Прерывание работы закрытием плагина может оставить фикстуру.

Числа предварительные, не производственные гарантии. `uiStopRoundTripMs` измеряет время от нажатия Stop до получения итогового отчёта в одном UI-clock. `stopToCleanupMs` измеряет задержку от получения stop в main до начала очистки и не учитывает доставку сообщения и саму очистку. Синхронный API и exportAsync нельзя обещать прервать; после stop новые фазы не запускаются, текущий экспорт ожидается.

Этот стенд покрывает чтение/экспорт и stop, но не очередь, дедупликацию, импорт и сроки жизни. Все лимиты из design §8 и итог задачи 1.6 остаются открытыми до измерений и последующих проверок рабочего моста. Cursor и продолжение здесь не реализованы: усечённый результат явно помечен неполным.
